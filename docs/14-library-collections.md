# 14. ライブラリとコレクション ―― ウェルカム画面の本棚

改善要望5(2026-09-08 立案、2026-09-09 実装)で、ウェルカム画面を「開くボタンと履歴2列」から
**本棚**へ作り直しました。お気に入りはこれに置き換わり、入り口をフラグで閉じてあります
(→ [06](06-persistence.md#一覧)、[13](13-history-and-known-limitations.md#経緯主な方針転換))。
検討の経緯と、実装中に計画から変えた点の一覧は
[plans/library-collections-study.md](plans/library-collections-study.md) /
[plans/library-collections-plan.md](plans/library-collections-plan.md)(段階 4.5・5.6〜5.23)に
そのまま残してあります。ここでは**今の形と、その理由**だけをまとめます。

## 用語と階層

```
ライブラリ(BookLibrary)          帯に並ぶ大分類。必ず1つ以上ある(既定のライブラリ)
 └─ コレクション(BookCollection) 本を束ねた棚。ウェルカム画面ではカバーを敷き詰めた「札」
     └─ 本(CollectionItem)       1冊。セキュリティスコープ付きブックマーク + パス + inode
```

- 階層は **2段で固定**(お気に入りの `FavoriteFolder` のような入れ子は作らない)。棚の一覧として
  それ以上の深さはかえって扱いにくい、という判断。
- 名前の重複は**同じ親の中で**禁止(前後の空白を除いた完全一致、大文字小文字を区別)。
  別のライブラリなら同名のコレクションでよい。
- **既定のライブラリは名前を持たない**(`BookLibrary.usesDefaultName`)。表示のたびに表示言語で
  「ライブラリ」/「Library」を組み立てる。作った時点の文字列を DB に残すと、日本語訳を入れる前の
  ビルドで一度起動した環境が英語のまま直らなかった(ユーザー報告)。既定のライブラリは
  **全言語の既定名を塞ぐ**(`occupiedNames`)―― 日本語表示で「ライブラリ」を別に作れると、
  英語へ切り替えた瞬間に同じ名前が2つ並ぶ。ユーザーが名前を付けた時点で追従をやめる。
- **空のコレクションは作らない**(`CollectionStore.createCollection`)。「＋」で名前を決めた直後は
  まだ行が無く、1冊目が入った時点で行ができる。1冊も入れずに「本を追加」パネルを閉じれば
  何も残らない = 閉じる操作がそのまま取り消しになる。
- **「本を追加」パネルは「＋」から作ったときだけ出す**(`PendingCollectionCreation.fromDrop`。
  ユーザー指示 2026-09-09)。ドロップで作ったコレクションには入れたい本がもう渡っているので、
  名前を決めた直後に空のパネルが出るのは、棚を1つ作るたびに閉じるだけの手間が増えるだけ。
  「＋」から作ったときは本を入れる場がそこにしか無いので、従来どおり開く。
- 同じコレクションに同じ本は入らない(`add(_:to:)` がパスと inode の両方で弾く)。

## ストア: CollectionStore

`FavoritesStore` と同じ作り・同じ約束事(→ [06](06-persistence.md#swiftdata-の使い方--踏んだ落とし穴と規約)):
`#Predicate` を使わない全件フェッチ+辞書キャッシュ、`@Attribute(.unique)` を付けない、
実在確認は非同期(`existenceByItemID`。契機はアクティブ化・ボリュームの着脱)で表示側は
辞書を読むだけ、`saveAndNotify` で保存と `.collectionsDidChange` を1回にまとめる。

`FavoritesStore` と違うところ:

- **メニューバーに出ない**ので `AppStores.allObjectWillChangePublishers` に**意図的に足していない**。
  コレクションを作り替えてもメニューバーは作り直されない(お気に入りの publish がメニュー全体を
  作り直していた轍を踏まないため。→ [03](03-architecture.md#アプリ全体で1つのもの))。
- 並び順はストアが持たない。ウインドウごとの `WelcomeLibraryState` が持ち、
  `collections(in:sort:)` / `items(in:sort:)` へ都度渡す(同じデータを別のウインドウが別の並びで
  見られる)。
- 件数・階層の上限は無い。
- **まとめて消す経路**を持つ(`delete(_ collections:)` / `remove(_ items:)` / `move(_ collections:to:)`)。
  1件ずつ既存の API を呼ぶと保存と通知がその回数だけ走る。複数の本にまたがる通知には
  `bookID` を付けない。
- コレクションのライブラリ間の移動は、**移す先に同名があれば動かさない**(まとめて動かすときは
  1つでも衝突したらその行き先ごと選べない ―― 選んだうちのどれが動いてどれが残ったか読めない
  状態を作らない)。UI は `canMove(_:to:)` で先に見て、理由を項目名に添える。
- **「本を別のコレクションへ移す」は無い。** 一度入れて同日に撤回した ―― 自動登録フォルダを
  持つコレクションから移しても次の走査で戻ってくるので、成立したりしなかったりする操作になる。
  移したいときは移す先へ足してから元から外す。

`LibraryCleanupViewModel`(保存データの削除)と `MetadataEditorViewModel`(知っている本)と
`BookExportViewModel`(URL の解決)は、コレクションの登録も数える・使う。

## カバー画像

| 部品 | 役割 |
|---|---|
| `CollectionCoverStore`(actor) | `~/Library/Application Support/<bundle id>/CollectionCovers/<CollectionItem.id>.jpg`。長辺 768px、JPEG 0.8。**切らずに**保存する |
| `CoverImageResolver`(nonisolated) | 「この本のカバーはどの画像か」を決める唯一の場所(上書き > 実効1ページ目)と、枠へ収める切り方 `cropped(_:to:anchor:)` |
| `CollectionCoverExtractor`(MainActor) | アプリ全体で1本の待ち行列。**同時1件**、上から順に埋まる。本を丸ごと開いて先頭ページを復号するので、並列にするとビューアの邪魔になる |
| `CollectionCoverThumbnail` / `CollectionTile` | 描く側。`CGImageSourceCreateThumbnail` で描く大きさだけ読み、`LazyCellImageBudget` で画面外セルの分を数える(`LazyVGrid` は画面外セルを解放しない) |
| `CollectionTileImageStore`(actor) / `CollectionTileImageCache` | 焼いた札の絵(下記)。`~/Library/Caches/<bundle id>/CollectionTiles/<BookCollection.id>-<署名>.jpg` と、その復号済みメモリ LRU |

**Caches ではなく Application Support** に置くのは、消えると登録してある本を**全冊**読み直すことに
なるため(未接続のボリューム上の本なら作り直せもしない)。キャッシュではないので上限も自動削除も
無く、リソースモニタの「ディスク上」にも上限を並べずに容量だけ出す。コレクション・本の登録・
「すべてのデータを削除」と一緒に消える。起動時に行の無いカバーを掃除する(`sweepOrphanedCovers`。
行のフェッチに失敗したときは**掃除しない** ―― 全部を孤児と誤認して消した経緯がある)。

**切り出しは保存時ではなく表示時**(2026-09-09 に変更。段階 5.10)。ライブラリごとに縦横比
(2:3 / 1:1 / 3:2、`CoverAspectRatio`)と、比が合わないときに残す位置(`CoverCropAnchor`:
start / center / end。切る軸は画像と枠の比から決まるので軸に依存しない3値)を選べるようにした際、
抽出時に切る方式だと**トグル1つでそのライブラリの全冊を読み直す**ことになり、未接続のボリューム上の
本は `.failed` へ落ちる。保存するのは切っていない画像1枚だけにして、比も位置も表示のたびに効かせれば
切り替えは即時かつ無損失(`CGImage.cropping(to:)` は部分画像を作るだけ)。既に切って保存してあった
カバーは、世代番号(`coverStorageGeneration`)で起動時に1回だけ全件 `.pending` へ戻して作り直す
(`markAllCoversPending` は save 1回)。

「自動 = 読み方向から決める」という位置指定は**廃止**した(入れた同日に撤回)。上下方向の切り出しに
読み方向は何も言えないうえ、読み方向を変えるとカバーの見た目まで変わるのは予想しにくい。

本ごとの上書き:
- **どの画像か** ―― `BookLayoutSettings.coverPageKey` / `externalCoverBookmarkData`。EPUB/CBZ の
  書き出しウインドウのカバー列と同じ行を読むので、どこで変えても3か所(コレクション・
  「メタデータの編集」ウインドウのカバー列・書き出しウインドウ)が一致する。
- **残す位置** ―― `BookLayoutSettings.coverCropAnchorRaw`(nil = ライブラリの設定に従う)。
  `hasCoverOverride` には数えないので「既定に戻す」で消えない。**コレクションの表示にだけ効き、
  書き出すカバーはトリミングしない**ので、書き出しウインドウのピッカーには出さない
  (`ExportCoverCell.showsCropAnchor`)。
- 抽出をやり直す契機は「どの画像か」が変わったときだけ(`.layoutDataDidChange` を自分が最後に
  使った値と比べる)。比・位置・読み方向では作り直さない。

実体が見つからない本は `.failed`(灰色)にせず `.pending` のまま置き、存在確認で「無い」と分かって
いる間は待ち行列へ積まない。存在確認の結果が変わったら `refill()` する。外付けが未接続のときに
待ち行列が回ると全冊 `.failed` になり、再接続しても二度と抽出されなかった(監査で指摘)。

カバーの選び直しは `CoverOverrideController`(元は `BookExportViewModel` の一部)に切り出してあり、
本を開いていない画面からも同じ操作になる。**`@State` に入れた `ObservableObject` は購読されない**
―― メタデータ編集シートがそうなっていて、位置を変えてもカバーもメニューのチェックも更新されない
不具合になった(ログでモデルは無罪と確認。macOS の SwiftUI では `.contextMenu` が `@State` の変化に
追随しない事例が複数報告されている)。今は `@Published revision` を出し、カバーとメニューの組を
`.id(revision)` で作り直す。

## 焼いた札の絵(タイルのキャッシュ)

札1枚は最大6冊のカバーを敷き詰めたもので、当初はセル1つ1つが自前の `.task` を持ち、カバーの JPEG を
**個別に**読んで復号し、表示のたびに切っていた。1画面に札が100枚載る棚では、それだけで600回の
ファイル読み・600回の復号・600本のタスクになる ―― スクロールが引っかかる、起動直後の最初のフレームが
遅れて**ウインドウの状態復元が目に見える**、という形で報告された(ユーザー報告 2026-09-09)。
1コレクション = 1ファイル = 1回の復号にすれば、そこが素直に6分の1になる。

**焼くのは「セルを隙間なく並べた1枚」だけ。** 余白・間隔・角丸・地の色・冊数バッジ・選択の枠・名前は
焼き込まない。

- 余白(8pt)と間隔(6pt)は札の幅が 120〜320pt と変わっても**変わらない**。余白ごと焼くと表示サイズへ
  縮めた瞬間に間隔まで縮み、「詰まりすぎて1枚の大きな絵に見える」と言われて広げたばかりのものが元へ戻る。
  隙間を焼かないぶん、この1枚の縦横比は札の大きさに依存しない定数になり、どの大きさでも歪まない。
- 地の色の既定は `Color.primary.opacity(0.07)` で、**明暗の外観で解決が変わる**。焼き込むと外観の
  切り替えだけで全札が作り直しになる。

割り付けの正典は `CollectionTileLayout`(余白・間隔・焼く画素数・セルの矩形)で、焼く側と描く側の
両方がここを見る。描くときは焼いた1枚から6つの矩形を `CGImage.cropping(to:)` で切り出して
`Grid` に並べる ―― 部分画像を作るだけで画素のコピーは起きない。

**焼けない札は今までどおりのセル方式に落ちる。** 抽出待ち(スピナー)・失敗(形式バッジ)・実体が
見つからない(淡く描く)が1つでも混じる札は、どれも状態で見た目が変わるものなので焼かない。
`existenceByItemID` は起動直後は空で `cachedFileExists` が既定 true を返すため、最初のフレームから
焼いた絵が使える。

**作り直しの契機**は指紋(`CollectionTileImageRequest.signature` = 比 + 描く item の並び + 切り出す
位置 + カバーの比)で、中身・並び・位置・比が変われば自動的に別ファイルになる。**カバー画像そのものが
差し替わったときだけは指紋が変わらない**(指紋に画像の中身は入っていない ―― 入れると札を描くたびに
6ファイルを stat することになる)ので、抽出した側が明示的に捨てる
(`CollectionCoverExtractor` → `CollectionStore.invalidateTileImages(forItemID:)`)。
古い指紋のファイルは、焼くたびにそのコレクションの新しい2枚だけ残して刈る(並び替えの設定が違う
2つのウインドウで署名が2つできるので1では足りない)。起動時に行の無いコレクションの札を掃除し、
128MB を超えたら古いものから捨てる。合成は同時4件までに絞る(`PageLoader` のデコード枠と同じ考え方)。

**メモリ LRU がグリッドの作り直しを見えなくする。** 予算超過で `.id(epoch)` ごと作り直すと画面内の
札が読み直しになるが、`CollectionTileImageCache`(署名+復号サイズが鍵、96MB)に復号済みで残っている
ので**同期で**描き直せる。ページ一覧グリッドは `PageLoader` のキャッシュがこれをやっているが、
コレクションのカバーにはメモリキャッシュが一つも無く、作り直しのたびに絵がいったん消えてから出てくるのが
見えていた(これが「スクロール時にカバー画像の読み込みがランダムに発生する」の正体)。
帳簿へは焼いた絵1枚を `cellCount = tileCellCount` として渡す ―― 1枚=1セルと数えると、下限セル数
(画面内に並びうる**カバー**の数から見積もる)に届くまでに6倍溜め込むことになる。

Caches に置くのは、カバーから数 ms で作り直せる**派生物**だから(カバー本体が Application Support
なのは上記のとおり別の理由)。リソースモニタの「ディスク上」には上限と並べて出す。

## ウェルカム画面の構成

```
WelcomeView(PanelSurface.welcome)
 ├─ WelcomeTopBar(44pt): [本を開く…][履歴から開く] | ライブラリのチップ(横スクロール) | ＋
 ├─ Divider
 └─ WelcomeLibraryPane
     ├─ LibraryPaneControls(右上): [ゴミ箱(編集中のみ)] ＋ 編集 並べ替え スライダー 歯車
     ├─ CollectionGridView(札の一覧。LazyVGrid .adaptive)      ← openedCollectionID == nil
     └─ CollectionDetailView(中の本。カバーの一覧)             ← 開いているとき
```

状態は `WelcomeLibraryState`(`ContentView` が `@StateObject` で1ウインドウに1つ):
選択中のライブラリ(UserDefaults `qooViewer.welcome.*` ―― `qooViewer.pref.*` ではないので
「初期設定に戻す」の対象外、全削除では消える)、開いているコレクション(保存しない。本を開いて
「ウェルカム画面へ戻る」で帰ると同じコレクションの中)、編集モード、並び順2つ、大きさ2つ、選択、
名前入力待ちの列、「本を追加」の対象。

**編集モード**(鉛筆)が決めるのは3つだけ:
1. クリックの意味 ―― 閲覧中は「開く/中へ入る」、編集中は「選ぶ」(左上の印+アクセント色の枠)。
2. ドロップの意味 ―― 閲覧中は「開く」、編集中は「コレクションを作る/本を足す」。
   空のときの案内文もこれに合わせて切り替える。
3. ゴミ箱を出すか、と右クリックの「削除…」「コレクションから削除」。

**編集モードを条件にしないもの**: ライブラリの作成・リネーム・削除・並べ替え、ペインの「＋」、
歯車、「メタデータの編集…」「Finderで開く」。当初は全部を編集モードの奥に置いていたが、
「区切り線の下のボタンを押さないと区切り線の上の名前を変えられない」「棚を作る・本を入れるのは
この画面で最初にやることなのに、モードの奥に隠れている」という指摘で外した。編集モードは
**画面が移ったら必ず抜ける**(ライブラリの切替・コレクションへの出入り・本を開いたとき)し、
選択は `isEditing` / `openedCollectionID` の didSet で必ず捨てる ―― 見えていないものをゴミ箱が
消さないため。

右クリックは **Finder と同じ規則**: 選んであるものを右クリックしたら選んだぶん全部、選択の外なら
その1つだけ(選択は変えない)。1つにしか意味の無い項目(開く・本を追加…・名前を変更…・新規◯◯で
開く・Finderで開く・メタデータの編集…)は複数選択中は淡色にする。

**シークレットウインドウ**は編集モードに入れない(`allowsEditing == false`。「＋」「編集」「歯車」
「履歴から開く」が無効、チップの右クリックもドラッグも効かない)。閲覧と、そこから本を開くことは
できる。コレクションの登録は DB への書き込みなので「何も記録しない」の約束から外れる
(→ [06](06-persistence.md#シークレットウインドウとその場限りの本))。

すりガラス面の輪郭(→ [09](09-ui-and-windows.md#パネルの面と文字の輪郭)): 帯の2つのボタンは
`.panelControlWell()` **と** ラベルへの `.panelOutlinedContent()` の両方 ――「標準のボタンは自前の
不透明な地を持つから何も要らない」は**誤り**で、背後の `BehindWindowVisualEffectView` に合わせて
描かれるベゼルは、重ね色を文字色にすると文字ごと消える(実測)。区切り線も輪郭。選択中のチップと
選択の枠は `.panelOutlinedAccent(in:)`。カバー・冊数バッジ・選択の印は自前の地を持つので何もしない。
ポップオーバー・シートの中身は macOS が不透明に描くので何も要らない。

実測して決めた細部(理由は各ファイルのコメント): ボタンの幅は `Button` ではなく**ラベル**に与える
(ベゼルは文字列の長さのまま枠の中央に置かれる)、チップの幅は名前ではなく2つのボタンと同じ
見積もりの固定幅、チップの並べ替えは `.draggable` ではなく `.onDrag(_:preview:)`(掴んだ瞬間が要る)
で落とし先はチップを丸ごと縁取る(挿入線はドラッグの絵の下に隠れて見えない)、履歴のポップオーバーは
行の高さを掛け算で見積もらず `onGeometryChange` で実測(そのため `LazyVStack` ではなく `VStack`)、
名前入力シートは 360pt に決め打ち。

## ドロップの振り分け

受け口はウインドウ全体に1つ(`ContentView.applyFileDropTarget`)。ウェルカム画面が出ている間だけ
`AppState.welcomeDropHandler` が手前に割り込み、編集モード中だけ引き受ける(それ以外は従来どおり
「開く」へ落ちる)。**`WelcomeView` の値を閉包に捕まえない**(AppState → 閉包 → View の写し →
`@EnvironmentObject` → AppState の循環で AppState が解放されなくなる。監査で指摘)。振り分けの本体は
状態を持たない `WelcomeDropHandling`。

`CollectionDropClassifier`(nonisolated、フォルダの列挙を伴う)が URL を3つに分ける:

| 落とされたもの | 扱い |
|---|---|
| 書庫/PDF/EPUB、画像を直接持つフォルダ、画像フォルダだけが並ぶフォルダ | **本**。ばらの本はまとめて1つのコレクション(名前を訊く) |
| 本のファイルが直下に並ぶフォルダ(棚) | **棚**。フォルダ名を既定の名前にしたコレクション1つ。複数落とせば名前入力を順に繰り返す |
| 空フォルダ、画像1枚、中間フォルダだけのフォルダ、対応しない拡張子 | 対象外 |

「本かどうか」「棚かどうか」の判定は `ShelfFolderResolver.role(of:order:)` と**1つ**
(→ [04](04-book-loading.md))。ドロップで棚と見なされたフォルダを別の経路が1冊と見なす、という
食い違いを作らないため。棚から入る本は**直下だけ**、並びはサイドパネルのフォルダブラウザと同じ
`SiblingBookOrder`。開いているコレクションへ棚を落としたときは中の本を展開して足す
(`booksToAdd`。何も起きないと黙って失敗したようにしか見えない)。

シートは別の `NSWindow` なのでウインドウ本体の受け口が拾えない。「本を追加」パネルとメタデータ編集
シートだけが `fileURLDropTarget`(URL を取り出すところは共通)を直に使う。「本を追加」パネルに
並ぶのは**この面で入れたぶんだけ**(id の配列で持つ。既に入っている本が並ぶと、いま落とした本が
どれか読めない)。

## 自動登録フォルダ

`BookCollection.autoFolderPath`(`String?`)。そのフォルダの**直下**に本が増えると、コレクションへ
自動で足される(`CollectionAutoFolderScanner`。アプリ全体で1つ)。

- **持つのはパスだけ。セキュリティスコープ付きブックマークは持たない。** フォルダを列挙する権限は
  `FolderAccessStore` が一手に持っている(→ [10](10-sandbox-and-security.md))。別のブックマークを
  持たせると同じフォルダの権限を2箇所が別々に開閉することになり、過去に漏れを出したのと同じ形。
  走査する側は `isPathCovered` に「いま列挙してよいか」を訊き、覆われていなければ**黙って見送る**
  (設定の面が「アクセスを許可」を出す)。代償として、フォルダを移動・リネームすると自動登録は
  静かに止まる。
- 拾う範囲は `ShelfFolderResolver.role` の `.shelf(books:)` そのもの ―― 同じフォルダを編集モード中に
  ドロップしたときと1冊のずれもなく一致する。棚でないフォルダ(空・それ自体が1冊・中間フォルダ
  だけ)は何も拾わないが、指定自体は弾かない(後から書庫が置かれれば棚になる)。
- **除外リストは作らない。** 手で外した本は次の走査でまた入る(ユーザーの判断:
  「それを嫌な人は自動登録フォルダを利用すべきではない」)。
- 初期値の入り方は3通り: フォルダをドロップ → そのフォルダ(権限も付いてくる)、ファイルを
  ドロップ → 全部が同じフォルダのときだけその親(**権限は付いてこない**)、「＋」→ 空欄。
  パスは**直接打てる**(`~` は展開しない ―― サンドボックスの中ではコンテナを指す)。打っている
  最中に DB へ書かない(ポップオーバーが下書きを持ち、Return と閉じたときに書く)、打っている
  文字列を横から正規化しない(末尾の `/` が消える)、注意書きの高さを常に予約する。
- 歯車は、一覧では**ライブラリの設定**(カバーの見せ方)、コレクションの中では**そのコレクションの
  設定**(自動登録フォルダ)を出す。開いている棚があるのにその外側の設定が出るのは筋が通らない、
  という判断。1つの歯車に2種類を入れるより読める。

**監視する**(`FolderChangeWatcher` = FSEvents の薄い包み。2026-09-09 に方針を変えた)。最初は
「見にきたときに走査すれば見え方は同じ」として監視を入れなかったが、要望は「コピーした瞬間に
増えてほしい」だった ―― 画面を見ながらコピーする。作りは同じ作者の qooLibrary
(`Sources/QooInfrastructure/Watch/FileSystemEventStream.swift`)がサンドボックス下で実測した結果に
合わせてある: `FSEventStreamCreate` は到達できない共有を含むと 30 秒ブロックしうるので生成は
メインアクターの外で(`watch(_:)` は async)、C へ渡すコールバックと箱は**ファイル直下**に置く
(`@MainActor` 型の内側だと FSEvents のキューから呼ばれた時点で落ちる)、`info` には `self` ではなく
箱を `passUnretained` で渡して retain/release は CF に任せる、パスを差し替えるときは
`FSEventStreamGetLatestEventId` を引き継ぐ(「今から」にすると隙間を取りこぼす)、`IgnoreSelf` は
付けない(このアプリ自身が自動登録フォルダへ本を書き出す)。イベントの中身は捨てて「何か変わった」
とだけ伝え、どの本が増えたかは走査側が一覧して決める(判定を2箇所に分けない)。

**`WatchRoot` も付けない**(実機で発覚 2026-09-09)。このフラグはルートの改名・移動を知らせるために
**ルートとその祖先ディレクトリを1階層ごとに open して握り続ける**(実測: ルート1本・深さ13で
DIR fd 13個、2本で26個、無しなら0個)。自動登録フォルダはコレクションの数だけルートになるので、
49個 × 5階層 = 245 で GUI アプリの fd の soft limit(256)を起動直後に使い切り、以後のあらゆる
open が EMFILE で落ちた ―― カバーが全部空になり、ドロップした本のブックマークも黙って作れなく
なった。改名・削除は走査が列挙して「見つかりません」に落ちるので、失うのは「改名した瞬間に
気づく」ことだけ。`FolderChangeWatcherTests` がルートの数で fd が増えないことを見張っている。

**監視だけに頼らない。** FSEvents はネットワークボリューム(SMB/AFP)では飛ばず、アプリが止められて
いる間の変更も取りこぼしうる。従来の契機(アクティブ化・ボリュームのマウント・画面の表示・
コレクションを開く・フォルダを設定した直後)は「取りこぼしの回収」として残してある。

**書き終わっていないファイルを登録しない**(`CollectionAutoFolderScan.isSettled`)。一律 10 秒待つ
最初の案は撤回した(即時反映を求められている以上、小さな本まで待たせる理由が無い)。更新時刻が
2 秒より古ければその場で通す(同じボリューム内の移動・リネームは元の更新時刻を引き継ぐので即座に
入る)。そうでなければ 0.5 秒以上空けた2回の観測で大きさも更新時刻も同じときだけ通し、どちらでも
なければ 0.5 秒後に見直す。判定は純粋関数なので実時間を待たずにテストできる。未来の時刻・読めない
ものは通す(通さないと永久に登録されない)。

`stat` とブックマークの生成はメインアクターの外で行う(落ちた共有のパスで 1 文字ごとにメインが
止まった。監査で指摘)。`releaseResources()` のあとに届いた走査の契機と結果は捨てる(遅れて来た
FSEvents のコールバックが解放済みの `ModelContext` に触った ―― テストで発見)。

## 環境設定・JSON・削除

- **環境設定「外観」→「ウェルカム画面」**(`PanelSurfaceSettingsView.welcomeSections`):
  「ライブラリ」セクション(一覧の札のコレクション名の大きさ)と「コレクション」セクション
  (カバーの下の表示: 表示しない(既定)/ ファイル名 / タイトル、その文字の大きさ)。
  コレクションごとの設定にはしない ―― 棚ごとに下の文字が変わると一覧として揃わず、作るたびに
  設定し直すことになる。「タイトル」は `MetadataEditorViewModel.initialDraft` をそのまま通す
  (登録済みなら DB、未登録ならファイル名からの推測)ので、「メタデータの編集」で見える文字列と
  食い違わない。推測は毎回その場で行い覚えない(1冊ぶんなら一瞬で、`LazyVGrid` が組み立てるのは
  見えているセルだけ)。**札の地の色**もここ(「ライブラリ」セクション)で、アプリ全体で1つ
  (`AppPreferences.collectionTileBackgroundColor`。**nil = 既定** = 明暗の外観に追従する薄い地で、
  行の右の矢印ボタンでそこへ戻せる)。一度はライブラリごとの設定だったが、帯でライブラリを
  選び直すたびに一覧の地の色が入れ替わるのは外観として落ち着かない、という判断で移した
  (ユーザー指示 2026-09-09。`BookLibrary.coverBackgroundColorRaw` はマイグレーションを
  起こさないためだけの名残)。カバーの縦横比・残す位置は**ライブラリごと**のままなので
  環境設定ではなく歯車(`LibrarySettingsPopover`)。設定パネルに説明文は置かない(ユーザー指示)。
- **JSON**(`formatVersion` 4、→ [08](08-export-and-import.md#ライブラリデータの-json-書き出し読み込み)):
  `libraries` → `collections` → `books` の素直な入れ子。カバー画像は含めない(取り込んだ先で
  抽出し直す)。ライブラリの縦横比・残す位置は Optional で、無ければ既定。自動登録フォルダは
  **パスだけ**を書き、取り込み側は**その場所に実際にフォルダがあるときだけ**、かつ**まだ設定されて
  いないときだけ**入れる。既定のライブラリは表示名で書き、合流は `occupiedNames` で見る(英語環境で
  書き出した `Library` が日本語環境の既定のライブラリへ入る)。
- **削除**: 「保存データの削除」はその本のコレクションの登録も消す(`removeItems(forBookID:)`。
  カバーも一緒に)。「すべてのデータを削除」は `CollectionCovers/` ごと消す。書き出し後の
  「保存データ: 削除」はコレクションの登録に**触れない**(手で登録したもの)。

## 「ウェルカム画面へ戻る」

`ViewerAction.returnToWelcome`(本だけ閉じてウインドウ/タブは残す)。ツールバー左端とサイドパネルの
モード切替の左のボタンが主な入り口で、**キー・マウスとも既定の割り当ては無い**。実体と橋渡しの
注意点は [09](09-ui-and-windows.md#キーkeybindingstore--remappablekey--vieweraction)。

画像の右クリックメニュー(`ViewerView.contextMenuContent`)のいちばん下の項目も、同じ
`ViewerAction.returnToWelcome` を呼ぶ。**表示は「本を閉じる」**(ユーザーの指示)で、環境設定の
最後のページ/書き出し後の動作にある同名の選択肢(`PageBoundaryBehavior.closeBook` /
`BookExportCompletionBehavior.closeBook` = `.closeTab` = タブごと閉じる)とは**動作が違う**点に注意。
文言を触るときは両方を見比べること。
