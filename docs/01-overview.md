# 01. 概要と設計の考え方

## qooViewer とは

macOS 15 以降で動く、漫画・コミック向けの画像ビューアです。SwiftUI + AppKit + SwiftData で書かれ、
Mac 用の古いビューア **cooViewer** に着想を得ています(操作の既定値 ―― キー割り当て、マウス、
表示モード、スクロール送り ―― は、対応する機能がある範囲で cooViewer に合わせてあります。
`KeyBindingStore` / `ViewerAction` / `ScalingMode` / `WheelScrollBehavior` のコメントに、
cooViewer のどの設定・どの action 番号に相当するかが書いてあります)。

開ける「本」は次の6種類です。

| 種類 | 実体 | 備考 |
|---|---|---|
| フォルダ | 画像ファイルを含むフォルダ(サブフォルダ・書庫を再帰的に含む) | 並び順はファイル名(→ [07](07-page-order-layout-bookmarks.md)) |
| zip / cbz | ZIPFoundation で読む | ファイル名の文字コードを書庫単位で自動判定 |
| rar / cbr | Unrar.swift(フォーク)で読む | Unicode 名を持たない古い RAR4 は文字化けする(ライブラリの制約) |
| 7z / cb7 | SevenZip.swift(フォーク)で読む | ソリッド書庫を必要な分だけ伸長する(→ [11](11-forked-dependencies.md)) |
| PDF | CGPDFDocument で描画、PDFKit でアウトライン | ページ順は文書自身のもの |
| EPUB | 固定レイアウトの画像 EPUB のみ | spine の順とページ単位の見開き指定を持つ唯一の形式 |

このほか、画像ファイルを直接渡すと(1枚でも、Finder で複数選択しても、最大 1000 枚まで)
**その場限りの本**として開けます(`MangaBook.BookOrigin.imageFiles`)。書庫の中の書庫(入れ子)も
どの深さでも辿れます。

本棚は持ちません。ウェルカム画面(または Finder・ドラッグ&ドロップ・お気に入り・履歴)から
本を開き、読み終えたら閉じる、という使い方を前提にしています。

## 主な機能(引き継ぎに必要な範囲)

- ページ送り(見開き/単ページ、右開き/左開き、4つの拡大縮小モード、スクロール送り)、
  スライドショー、拡大鏡、ピンチ拡大、実寸表示ウインドウ
- ページ一覧パネル、プログレスバーのフィルムストリップ、サイドパネル
  (フォルダブラウザ/本の中身/お気に入り+ブックマーク/履歴/ページ一覧/リソースモニタ)
- ブックマーク(本の中のページの印)とお気に入り(本そのものの登録、階層フォルダ付き)
- ページレイアウト(ページの並べ替え・除外・見開き左右の固定・読み方向の上書き・自動レイアウト)
- 書誌メタデータ(著者・タイトル・シリーズ・巻数。ファイル名からの推測ルール付き)
- 本の書き出し(EPUB / PDF / CBZ)、画像の書き出し、ライブラリデータの JSON 書き出し・読み込み
- 複数ウインドウ・タブ、シークレットウインドウ(何も記録しないウインドウ)
- 表示言語(日本語/英語)と外観(ライト/ダーク)を OS と独立に切り替え
- App Sandbox 下で動作(フォルダのアクセス権を環境設定で管理)

機能の使い方は [MANUAL.md](../MANUAL.md) を参照してください。

## 設計原則 ―― なぜそうなっているか

コードのコメントを横断して読むと、次の考え方が繰り返し現れます。これらは明文化された規則では
なく、不具合と要望に応えるうちに定着したものです。新しい変更もこの線に沿わせてください。

### 1. 実測してから決める

推測で2回外したら、必ず計測してから直します。実際に、

- 画像表示のメモリは「CGImage を表示すると元の約3倍(CoreAnimation のテクスチャ+CG のラスタ
  コピー)」「malloc の大きなブロックは解放しても footprint が戻らない(mmap なら戻る)」という
  実測から、`PagePixelBuffer`(mmap 裏打ちの画素バッファ)が生まれました(→ [05](05-page-display-and-memory.md))。
- SwiftUI の `Image.Interpolation` は `.medium` と `.low` が CALayer では同じ描画になることを
  レイヤーツリーの実測で確認し、「低画質」の選択肢を廃止しました(`InterpolationQuality`)。
- 環境設定の `.confirmationDialog` はボタンが3つまでしか出ないことを実機で確認し、自前のシートに
  置き換えました(`PageBoundaryChoiceSheet`)。
- ソリッド 7z を「前後交互に」読むと 10 秒が 230 秒になることを計測し、書庫順に読む規約を
  作りました(`ViewerViewModel.warmUpWideImageCacheForEntireBook`)。

計測のやり方は [12](12-verification-and-debugging.md) にまとめてあります。

### 2. 「記録が残る経路」と「残らない経路」を厳密に分ける

シークレットウインドウ(`AppState.isPrivateWindow`)と、その場限りの本(`MangaBook.isTransient`)
では、読書位置・ブックマーク・レイアウト・メタデータの取り込み・履歴・ディスクのサムネイル
キャッシュを**一切書きません**。「ファイルに入っている情報(EPUB の目次など)は読んでよいが、
qooViewer 側の記録は残さない」という線引きです。ViewerViewModel の `skipsPersistence` が唯一の
判定で、DB へ挿入しない独立したモデルインスタンスを使うことで「書いても残らない」二重の安全策を
取っています(→ [06](06-persistence.md#シークレットウインドウとその場限りの本))。

同じ理由で、「すでに開いている本のウインドウを前面に出す」判定も**同じ性質のウインドウ同士**
でしか行いません(`LaunchCoordinator.openAppState(forBookAt:isPrivate:)`)。

### 3. ファイル側の情報は「種」、DB が「権威」

EPUB / PDF / ComicInfo.xml が持つ読み方向・見開き指定・目次・書誌情報は、**本を初めて開いたときに
1回だけ**DB へ取り込み、以後は DB に従います(`LayoutStore.importSourceLayoutIfNeeded`、
`BookLayoutSettings.didImportSourceLayout`)。以前は「ファイルの指定が常に勝ち、ユーザーの操作を
ロックする」設計でしたが、「取り込んだ結果ユーザーが何も変えられない」のを避けるために転換
しました(→ [07](07-page-order-layout-bookmarks.md#ファイル側のレイアウトは1回だけ取り込む))。

### 4. ユーザーのデータを勝手に消さない

- 自動削除(`LibraryDataPruner`)の対象は読書位置とブックマークだけで、しかも上限件数を超えた
  ときに古いものからに限ります。レイアウト・メタデータ・お気に入りは無制限に保持します
  (「手間をかけて登録した情報がアプリの都合で消えることを避ける」)。
- 環境設定の「初期設定に戻す」は、値を下げるとデータが消える設定(保持件数)を意図的に対象外に
  します(`AppPreferences.keys(for:)`)。
- 全削除は環境設定の「リセット」画面だけから、確認→実行→終了、の手順でしか行えません。

### 5. 既定値のままなら見た目も挙動も変わらない

新しい設定を足すときは、**既定値を「これまでの見た目と1ピクセルも変わらない値」**にします
(すりガラスの面ごとの設定、フィルムストリップ、文字の影、常時表示の帯のすりガラス、など)。
逆に既定を変えた例(サムネイルのディスクキャッシュを既定 OFF に)では、コメントに理由
(黙って数百 MB 使っていた)を残しています。

### 6. 同じものを別の語で呼ばない、同じ種類の画面は同じ形にする

UI の文言には用語表があり(下記)、補助ウインドウ(メタデータの編集・書き出し3種・ブックマーク/
レイアウトの編集・お気に入りの整理・保存データの削除・履歴の削除)は「ツールバーに操作、
一覧はその下へ潜る、件数は下部中央のステータスバー」という同じ形に揃えてあります
(→ [09](09-ui-and-windows.md#一覧ウインドウの共通の形))。

### 7. 判断は1箇所に集約する

同じ判断を複数箇所に書くと片方だけ直し忘れる、という不具合が実際に何度も起きたため、
「唯一の適用点」を持つ型が多くあります。

| 判断 | 集約先 |
|---|---|
| ページの実効順(並び順の設定 → 並べ替え → 除外) | `EffectivePageOrder` |
| どの WindowGroup で開くか(通常/シークレット) | `BookWindowGroup` |
| 落とされた/渡されたファイル群を何冊の本にするか | `BookOpenRequest` |
| 新しいウインドウ/タブで本を開く手順 | `BookWindowOpener` |
| 書き出し形式ごとの差 | `BookExportFormat` |
| ページ1枚/本1冊の右クリックメニューの中身 | `PageContextMenuItems` / `BookOpenContextMenuItems` |
| 環境設定の画面一覧 | `SettingsPane` |
| 書庫のファイル名の文字コード判定 | `EntryNameDecoder`(書庫単位) |
| ファイルのドロップの受け口 | `BookFileDropTarget` |

### 8. プラットフォームの癖には「検索 → 実測 → 堅牢側」

AppKit / SwiftUI 自体の不具合と疑われる挙動(ウインドウ状態復元、`FocusedValue`、メニュー再構築、
`Settings` シーンのリサイズ不可、`Group` の中の `EmptyView` が幅を持たない、など)は、まず既知の
報告を検索し、次に最小再現で実測し、報告者の環境で再現しない場合は堅牢な側の実装に倒します。
その結果は必ずコメントに残します。

### 9. コメントに「なぜ」を書く

このリポジトリのコメントは「何をしているか」より「なぜそうなったか」を優先します。
不具合の再発防止に効くのは後者だからです。既存のコメントを消さず、変更したら更新してください。

## 用語表

UI の文言とコードの語彙で、同じものを別の語で呼ばないための表です。

| 用語 | 意味 | コード上の対応 |
|---|---|---|
| 本 | フォルダ・書庫・PDF・EPUB・画像群のいずれか1冊 | `MangaBook` |
| bookID | 本の識別子。フォルダ/ファイルの**パス文字列そのもの** | `MangaBook.id` |
| ページ | 本の中の画像1枚(PDF は1ページ) | `PageRef` |
| ページの鍵 / pageKey | ページを並び順に依存せず指す文字列(`PageRef.sortKey`) | DB の `pageKey` 列 |
| 正準順 | ファイル名の Finder と同じ照合(`localizedStandardCompare`)による並び | `PageOrder.canonical` |
| 従来順 | 1.36 以前の並び(`.numeric` 比較)。古い行の番号はこの並びで記録されている | `EffectivePageOrder.legacyOrderedPageKeys` |
| 実効順 | 設定と並べ替え・除外を適用した、実際に読む並び | `EffectivePageOrder.orderedPages` |
| 読書位置 | 本ごとの「最後に読んでいたページ」と表示設定 | `BookReadingState` |
| ブックマーク | 本の中のページに付ける印(**セキュリティスコープ付きブックマークとは別物**) | `Bookmark` |
| セキュリティスコープ付きブックマーク | サンドボックスで次回もファイルへ触るための `bookmarkData` | 各モデルの `bookmarkData` |
| お気に入り | 本そのものの登録(階層フォルダ付き) | `FavoriteBook` / `FavoriteFolder` |
| 履歴 | 最近開いたファイル | `RecentFilesStore` |
| レイアウト | 読み方向の上書き・見開き強制・ページ順補正・ページ単位の状態 | `BookLayoutSettings` / `PageLayoutOverride` |
| 除外(非表示) | 読書フローから完全に外したページ | `PageLayoutState.excluded` |
| 見開き右 / 見開き左 | **画面上の**右/左に置く指定(読み方向に応じて「どちらと組むか」が変わる) | `PageLayoutState.spreadRight/Left` |
| 保存データ | 本ごとに DB へ保存したものの総称(読書位置・ブックマーク・レイアウト・メタデータ) | ― |
| 書き出し / 読み込み | ファイルを作る / ファイルから取り込む(「エクスポート/インポート」とは呼ばない) | `*Exporter` / `LibraryImportExportService` |
| 保存先 | 書き出したファイルを置くフォルダ | `LastUsedFolderMemory` |
| 削除 | 取り消せない消去。「消去」「クリア」とは呼ばない | ― |
| 冊 | 本を数える単位 | ― |
| シークレットウインドウ | 何も記録しないウインドウ | `AppState.isPrivateWindow` |
| その場限りの本 | 画像ファイルから直接作った本。記録しない | `MangaBook.isTransient` |
| 面(パネルの面) | すりガラスで描いている領域(ページ一覧・ツールバー・プログレスバー・サイドパネル・ウェルカム・その他) | `PanelSurface` |
| 表示モード | 拡大縮小の4モード(画面内に収める/横幅に合わせる/横幅に合わせる(単ページ)/拡大縮小しない) | `ScalingMode` |
| 見開き / 単ページ | 一度に2ページ見せるか1ページか | `DisplayMode` |
| 右開き / 左開き | 読み方向 | `ReadingDirection` |
