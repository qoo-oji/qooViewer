# ハングアップとクラッシュ ―― コード全体の監査(2026-10-25)

[code-audit-2026-10-05.md](code-audit-2026-10-05.md) は差分を対象にした監査だった。今回は**コード全体**(約 15 万行)を対象に、ハングアップと
クラッシュに繋がりうる所だけを探した。範囲を 8 つ(書庫・解析 / 並行処理・XPC / ファイル操作・監視 / 起動・終了・ウインドウ / ビューア /
保存データ / ホームの一覧 / 書き出し・その他)に分け、同じ点検表で読んだ。

- クラッシュ: 強制アンラップ・添字・整数の溢れ・実行時のアクター判定・continuation・AppKit の例外・SwiftData
- ハング: メインでのブロック・同期待ち・協調スレッドの枯渇・終わらないループ

主な指摘は経路を読み直して判定してから直した。直した差分は別の 3 人で読み直し、そこで出た指摘も同じ段で直した。

凡例: **確定**(経路を全部辿った)/ **見込み**(フレームワークの振る舞い・時機に依存するか、読んだ人だけが辿った)。

## 2. 軽微

- 入れ子の書庫の幅に上限が無かった → 1 回の読み込みで 1 万個まで。
- 並べ替えに重なった鍵があると、同じページが 2 回並んだ。本の側に同じ sortKey が 2 枚あると、片方が消えた → 書かれた回数だけ、元の並びの順に割り当てる。
- `hasRoomForStaging` の `st_size + margin` が溢れうる。負の `st_size` で `UInt64(…)` が trap しうる → どちらも丸める・断る。
- 自動リネームの `visit` とフォルダの `merge` が再帰していた(深い木で FileIO のスレッドのスタックを使い切りうる)→ 明示の積み上げ。
- 自動リネームのマウントの知らせの購読が `receive(on:)` 無しで `assumeIsolated` していた。
- メインで止まりうる問い合わせ:
  - 「このアプリケーションで開く」の名前・アイコン(ネットワーク上のアプリはファイル名で表示する)
  - 同期の `NSWorkspace.open`(→ `openWithoutWaiting`)
  - 一時フォルダの判定の `standardizedFileURL`
  - アンマウント前の記述子の解放
- PageLoader の actor の上の PDF の日時・フォルダの ComicInfo の読み → `FileIO`。
- 新しい窓を探す 2 か所と起動の窓を隠す見張りが、アラート・パネルを窓と取り違えうる → `BookWindowOpener.isContentWindowCandidate`。
- ストアを開けないとき、空き・書き込み権限が原因でも削除を勧めていた。作り直しも失敗すると `fatalError` → 空きが 10MB 未満・書けないなら理由を出して終了。
- `exportBookmarks` が await をまたいで `Bookmark` の行を読んだ → 待つ前に値へ写す。
- その他:
  - 表紙の元画像の読み込み(`FileIO`)
  - リソースモニタの持ち主ごとの答え(1.5 秒まで、前の問いに答えていない持ち主には尋ねない)
  - アイコン表示のレイアウトの `Int(…)`(無限の矩形)
  - ツリーの `roots[index]` と `node.children?[index]` の範囲(`?` は範囲を確かめない)
  - 書き出しの窓を閉じたら書き出しを止める
  - 上書きの確認の continuation を置き換える前に解く

## 3. 直していないもの

- **`FileIO` のスレッドが増え続けうる**: 期限で待つのをやめても I/O は止まらない(設計上の性質)。マウントごとの見張りが要るので別の作業にする。
- **PDF の書き出しが協調スレッドで I/O をする**: docs/08 で受け入れ済み。
- **リソースモニタが本の統計(`fetchBookSnapshot`)を待つ所**: その窓のモニタが止まるだけ。
- **書き出しの 1 冊ごとの `lastShownDisplaySettings` の全件の取り直し**: 本の読み込みに比べて無視できる。
- **書き出し先そのものが応答しない**: 書き込みは待つ(Finder と同じ)。

## 4. 退けたもの

- 閉じたウインドウのデリゲート(`BookClosingWindowDelegate`)へ通知が届いて落ちる、という指摘: デリゲートを持つのは関連付けだけで、手放した時点で解放され、通知の登録は弱参照なので外れる。
- 起動時の復旧の警告をランループのブロックへ移す案(一度入れて戻した): モーダルの間に作られた本の窓はキーにもメインにもなれず、窓の置き場所を当てる見張りが働かない。見えないアラートで止まって見えた件は、見張りの取り違えを直して解いた。
