# メタデータを作る役を 1 つにする ―― 計画(2026-09-22)

利用者の指摘(2026-09-22)から。メタデータの編集ウインドウでシリーズ名を直すと、ときどき直す前の名前に戻った。原因を調べると、
ファイル名からメタデータを作って DB へ書く役が 5 か所にあり、見比べる本の範囲がそれぞれ違っていた。利用者の方針:

- **メタデータは本の情報で、どの機能の持ち物でもない**(書き出し・シート・メタデータの編集ウインドウ・ライブラリ・スマートライブラリが
  読む)。作って書くのは 1 か所。
- **スマートライブラリは、対象フォルダの中にどの本があるかを保存データとして記録するだけ**。メタデータは読むだけ。
- 機能の ON/OFF でメタデータの対象は変わらない。スマートライブラリもライブラリも、OFF の間は**最後に記録した本の一覧**を使う。

## 1. 今の形(書き手 5 つ)

| 書き手 | 見比べる本 | 書くもの |
|---|---|---|
| メタデータの編集ウインドウ(`MetadataWorkspace`) | このアプリが知っている本 + スマートライブラリの対象フォルダの本 | 行の無い本を作る・ロックしていない行の値・直した欄・ロック |
| スマートライブラリ(`SmartLibraryCatalog.registerParsed`) | 対象フォルダの本だけ | 行の無い本を作る・ロックしていない行の値 |
| 本を開いたとき(`BookMetadataStore.registerParsed`) | その 1 冊だけ | 行の無い本を作る |
| EPUB/PDF/ComicInfo の取り込み(`importSourceMetadata`) | その 1 冊だけ | 直した欄と値 |
| 規則を変えたとき(`AppStores` → `reparseUnlockedRows`) | 行のある本すべて | ロックしていない行の値 |

起きていたこと:
- 同じ本でも書き手ごとにシリーズの読み(錨)が変わり、DB には最後に書いた側の値が残る。
- 書くたびに `bookMetadataDidChange` が飛び、ほかの書き手が集め直して書く(スマートライブラリは `metadataStore.revision` で集め直す)。
- その知らせが、メタデータの編集ウインドウの「直しが DB へ届く前」に当たると直しが戻った(`MetadataWorkspace.knownStates` で
  塞いだ。docs/07)。
- ライブラリは値を作らず読むだけだが、行の無い本は `BookTitleResolver` がその場で 1 冊だけ読んだ値を**保存せずに**出す
  (ほかの本と見比べないので、ウインドウで見えるシリーズが出ない。メタデータでの検索にも掛からない)。

## 2. 新しい形

### 2.1 メタデータ生成(`MetadataGenerator`、アプリで 1 つ。`AppStores`)

- **ファイル名からメタデータを作って DB へ値を書くのは、ここだけ。** 持つのは qooMeta の索引(`ProposalIndex`)1 つ。
- **対象の本**(母体)= 次の和。除外フォルダの中の本は入れない。
  1. このアプリが知っている本のうち、機能に属さないもの ―― 読書位置・ブックマーク・レイアウト・お気に入り・メタデータの行
     (`KnownBooks` からコレクションを除いたもの)。
  2. **コレクションの本の一覧(記録)** ―― ライブラリが ON の間に `CollectionStore` から写して保存したパスの一覧。
     OFF の間はこの記録を使い、`CollectionItem` は読まない(CLAUDE.md の約束どおり)。
  3. **スマートライブラリの対象フォルダの本の一覧(記録)** ―― スマートライブラリが探した結果を保存したもの。OFF の間はこの記録を
     使う(探し直しは止まる。OFF の間に増えた本は、ON に戻して探し直したときに加わる)。
- **入力**: 本ごとに、名前・ルールセット(利用者が選んだものか自動)・確定した内容(ロックした行はすべての欄、していない行は直した欄。
  `BookMetadataRecord.confirmation`)。全冊を 1 つの索引に入れるので、錨はいつも同じ母体で決まる。
- **書くもの**: 行の無い本はロックせずに作る。ロックしていない行は、読みが変わったら値を書き直す。**ロックした行・直した欄・
  ロック・ルールセットは書かない**(それは利用者の操作の側が書く)。書く知らせは 1 つにまとめ、自分の書いた知らせでは動かない。
- **動く契機**(少し待ってまとめる):
  - 母体が変わった(本を初めて開いた・コレクションの記録が変わった・スマートライブラリの記録が変わった・保存データが消えた)
  - 規則が変わった(索引を作り直す)
  - 行の形(直した欄・ロック・ルールセット)が変わった(メタデータの編集ウインドウ・シート・取り込み・保存データの読み込み・付け替え)
    ―― その本だけを索引へ渡す(錨の効果で変わったほかの本も書く)
- **起動時**: 画面を出した後、裏で母体を集めて索引を読み込む(`load` は並列。2,439 冊で 1.3 秒の実測がある)。書くのは区切って
  (`upsertAllInBatches`)。
- 間引き(`pruneParsedOnlyRows`)は母体を使う(母体に無い、読みだけの行を消す)。

### 2.2 それぞれの画面・仕事

| もの | 変わること |
|---|---|
| スマートライブラリ(`SmartLibraryCatalog`) | 対象フォルダを探し、**本の一覧を記録する**だけ。qooMeta の索引と `registerParsed` を外す。並べるメタデータは DB の値(行がまだ無い本は、メタデータ生成が書くまでファイル名だけで並べる)。 |
| ライブラリ(`CollectionStore`) | コレクションの本の一覧が変わったら記録を書き直す(ON の間だけ)。値は作らない(今と同じ)。 |
| メタデータの編集ウインドウ(`MetadataWorkspace`) | **直した欄・ロック・ルールセットだけを DB へ書く**。値と提案(型に合ったか・推定した巻・シリーズの組)はメタデータ生成の索引から受け取る。自前の索引・`registerAll`・値の書き込みを外す。一覧に並ぶ本 = 母体。 |
| 1 冊ぶんのシート | 直した欄・ロックを書く(値の計算はメタデータ生成)。開いたときの初期値は DB の値。 |
| 本を開いたとき | `registerParsed` の代わりに「母体へ加える」だけ(シークレットウインドウは加えない ―― 今と同じ)。 |
| EPUB/PDF/ComicInfo の取り込み | 直した欄を書くだけ(値はメタデータ生成)。 |
| 規則の変更 | `reparseUnlockedRows` を外し、メタデータ生成が索引を作り直す。 |
| `BookTitleResolver` など、値を読む所 | DB の値を読む。行がまだ無い本だけ、今の 1 冊読みをつなぎとして残す。 |

### 2.3 機能の ON/OFF

- メタデータ生成はどの機能の ON/OFF でも止めない(メタデータはどの機能の持ち物でもない)。
- スマートライブラリ OFF: 画面と探し直しが止まる。記録した一覧は母体に残る。
- ライブラリ OFF: コレクションの記録を書き直さない(`CollectionItem` を読まない)。記録した一覧は母体に残る。
- 記録から本が外れるのは、探し直して本が無い・移った・対象フォルダが外された・コレクションから外したと分かったときだけ。

## 3. 段取り

1. **記録と母体**: コレクションの本の一覧・スマートライブラリの本の一覧を保存する形(Application Support、パスの一覧)と、母体を
   集める口。テスト(InMemoryLibrary)。
2. **メタデータ生成**: 索引・契機・書き込み。テスト(錨が母体で決まる・ロックした行に書かない・直した欄を書かない・自分の知らせで
   動かない・規則を変えたら読み直す・母体から外れた読みだけの行を間引く)。
3. **書き手を外す**: スマートライブラリの `registerParsed` と索引、本を開いたときの `registerParsed`、取り込みの値の計算、
   `reparseUnlockedRows`。スマートライブラリは DB の値で並べる。
4. **メタデータの編集ウインドウ**: 索引をメタデータ生成のものに替え、書くのは行の形だけにする。取り消し・ロック・再生成・ルールセットの
   切り替え・連番などの操作はそのまま(書く先が「行の形」になるだけ)。
5. **読む所の整理と docs**: `BookTitleResolver` のつなぎ、docs/07・14・CLAUDE.md、MANUAL/CHANGELOG(利用者に見える変化があれば)。

各段でテストを通し、段ごとにコミットできる形にする。

## 4. 気をつけること

- **索引をずっと持つ重さ**: 今はスマートライブラリの索引を画面が出ている間だけ持つ。アプリで 1 つずっと持つと、その分のメモリが
  常に要る。まず数千冊で実測し、重ければ「しばらく使わなければ手放し、要るときに `load` し直す」にする。
- **メタデータの編集ウインドウの速さ**: 直した本だけを索引へ渡す今の速さを保つ(索引が 1 つになるだけで、渡す量は同じ)。
- **ネットワークのボリューム**: 母体を集めるのに本へ触らない(パスの一覧と DB だけ)。名前の読みも パスから。
- **テスト**: メタデータの編集ウインドウのテスト(`MetadataWorkspaceTests`)は、書き先が行の形になるのに合わせて直す。
- **保存データの書き出し・読み込み**: 記録した一覧(コレクション・スマートライブラリ)は写しなので書き出さない(読み込んだら作り直される)。
