# シークレットフォルダ ―― 調査と決定事項(2026-10-03)

メタデータの編集ウインドウの「除外フォルダ設定」(`MetadataRulesStore.excludedFolders`。メタデータの登録だけを止める)を廃止し、
**履歴・保存データ・メタデータ全般を残さないフォルダ**として作り直す計画。§1〜§4 は調べた時点(コミット `2996d9a`)の記録。
**同じ日に実装した** ―― 実装で決めたこと・計画から変えたことは §5、仕組みの正典は docs/06「シークレットフォルダ」。

## 1. 位置づけ

**シークレットフォルダの中(サブフォルダを含む)の本を表示している間、その窓はシークレットウインドウとして振る舞う。**

- 判定は「窓」ではなく「表示中の本の場所」。シークレットとして振る舞う条件は `isPrivateWindow || 表示中の本がシークレットフォルダの中`。
- **どの経路で開いても**適用する(ホーム・次/前の本・コレクションやスマートライブラリの並び・サイドパネル・ドロップ・履歴・Finder/Dock)。
- ビューアの中でフォルダの外の本へ移ったら、**元がノーマルの窓ならノーマルへ戻る**(本ごとに行き来する。ホームへ戻るまで続く、ではない)。
  元からシークレットウインドウなら、シークレットのまま。
- シークレットとして振る舞っている間は、**見た目もシークレットウインドウと同じ**: 外観一式(`preferences.privateAppearance`。明暗と
  タイトルバーの色を含む)、タイトルの「(シークレット)」、書き込みを伴う
  項目の淡色(表示中の本に書く項目だけ。ほかの本・フォルダへの操作はノーマルのまま ―― 決定 15)。切り替わったときは本の下に短い知らせを出す(`postViewerNotice`)。利用者の言葉では「そうでないと本当に切り替わったのか
  わかりにくい」。

成り立つ理由: 本を開いている間ホームは破棄されている(`ContentView` が `WelcomeView` を `ViewerView` に差し替える)ので、
「シークレットとして振る舞う期間」はホームと重ならない。窓ごとのホームの状態(`FileBrowserState.isPrivate` など)は動的に変える必要が無い。

## 2. 決定事項(2026-10-03、利用者)

| # | 論点 | 決定 |
|---|---|---|
| 1 | 名前 | **シークレットフォルダ**(「除外」は除外ページ・自動リネームの除外と衝突、「記録」は用語表で避ける語) |
| 2 | 適用する経路 | すべての経路 |
| 3 | 外の本へ移ったとき | 元がノーマルならノーマルへ戻る |
| 4 | 外観 | シークレット用の外観一式に切り替える |
| 5 | 切り替えの知らせ | 本の下に短い知らせを出す |
| 6 | 主ウインドウの役割・外から開く本の受け皿(`actsAsRegularWindow`) | **残す**(窓の元の状態はノーマルなので、扱いを変えない) |
| 7 | 今のメタデータ用の除外一覧 | **新しい一覧へ移す**(対象が履歴まで広がる旨を一度だけ知らせる) |
| 8 | 一覧を保存データの書き出しに入れるか | **入れる** |
| 9 | ホーム側 | メタデータの自動生成から外す / 表紙のディスクキャッシュを書かない / コレクションへの追加は淡色で断る(自動登録でも入れない)/ スマートライブラリから外す |
| 10 | 自動リネームのログ・動画サムネイルの先回り | 先回りだけ止める。ログは今のまま(自動リネームはファイル操作で、対象は利用者が選んだもの) |
| 11 | 設定 UI の置き場所 | 環境設定の新しいペイン(「詳細」グループ、「フォルダのアクセス権」の隣)+ ファイルブラウザ/サイドパネルのフォルダの右クリック + インスペクタからのリンク |
| 12 | 既存の保存データ | シークレットウインドウと同じく**読むが書かない**。ペインにフォルダごとの残っている保存データ・履歴の冊数と「このフォルダ内の保存データを削除…」を置く |
| 13 | 移動への追従・保存データの読み込み | シークレットウインドウと同じく特別扱いしない(既存のデータは従来どおり追従・読み込みする) |

| 14 | `privateWindowsUseOwnAppearance` が OFF(既定)のとき | **設定に従う**(見た目は変わらず、手がかりはタイトルと知らせ)。ペインに「シークレット用の外観を別にすると見分けやすい」旨と外観へのリンクを置く |
| 15 | 右クリックからのシークレットフォルダの追加・削除 | **元からシークレットウインドウ**: 今までの約束どおり(パスを保存する項目は淡色。よく使う項目・自動リネームの規則と同じ。環境設定のペインはどの窓にも属さないので使える)。**ノーマルの窓でシークレットフォルダの本を表示中**: サイドパネルの操作はノーマルのまま(目的は開いている本の情報を残さないことで、ほかの操作までシークレットウインドウに揃える意義は薄い ―― 利用者)。シークレットに揃えるのは、表示中の本の書き込みと見た目(§1)だけ |
| 16 | 表示中の本のフォルダを追加・削除したとき | 表示中の本はそのままで、次に開いたときから効く(シークレットにするかは読み込みの前に決めるため)。それまでに書かれたものはペインの「このフォルダ内の保存データを削除…」で消せる |
| 17 | サイドパネルと履歴の表示 | **元のモードに従う**(利用者)。ノーマルの窓ではサイドパネルの履歴も File ▸ 最近開いたファイルも隠さない(表示中の本は記録されないので、そこに現れない)。表示中の本に書く項目(ブックマークの＋など)だけは淡色 |

## 3. 書き込み口の洗い出し(2026-10-03)

### 3.1 表示中の本で決まるもの(実効の判定へ切り替える)
`skipsPersistence`(`ViewerViewModel`、`AppState.open` 内の局所変数、`ContentView` の `ViewerHandoff` を作る所)が守っているもの一式:
履歴、前回の本(`ContentView` の `LastActiveBookStore.record`)、読書状態、ブックマーク(手動・EPUB の目次・PDF のしおり)、
レイアウト(ファイル由来の取り込みを含む)、ファイル由来のメタデータの取り込み、`MetadataGenerator.noteBookOpened`、bookID の追従・
識別子の補完・ページキーの修復、サムネイルとページ寸法のディスクキャッシュ。加えて:
- **ページ一覧キャッシュ**(`AppState.open` の `cachesPageList`)は `isPrivateWindow` しか見ていない(`leavesNoRecord` も見ていない)。
  読み込みの前に要求の URL で判定する。
- **進め方: シークレットフォルダの本を「保存データに何も残さない本」(`MangaBook.leavesNoRecord`)に加える**(決定 17 で決まった)。
  既存のコードは「窓がシークレット」(`isPrivateWindow` ―― 履歴の表示・ほかの本やフォルダへの操作)と「表示中の本が何も残さない」
  (`leavesNoRecord` ―― その本への書き込み)を既に分けている(2026-09-23 の監査。サイドパネルの `isPrivateWindow` と
  `allowsLibraryEditing`、メニューの `isPrivateWindow || currentBookLeavesNoRecord`、`activeRecordableBookAppState`)。
  決定 15・17 の「サイドパネルなどは元のモード、表示中の本の書き込みだけ止める」は、その場限りの本の扱いとちょうど同じなので、
  **`isPrivateWindow` を読む約 180 か所の仕分けは要らない**。場所の判定は開いた時点の値を本に持たせる(読み込み中に一覧が変わっても
  揺れないように)。
- `isPrivateWindow` から実効の値へ切り替えるのは見た目だけ: 窓の外観の揃いを選ぶ所(`ContentView.body`)、タイトルの「(シークレット)」
  (`WindowTitle`)、切り替わりの知らせ。どれも `AppState.currentBook`(新しい本が表示された瞬間)で決める。
- 同じ本の二重オープンの判定(`LaunchCoordinator.openAppState(forBookAt:isPrivate:)`)と主ウインドウの役割は窓の性質のまま(決定 6)。
- 不採用: 窓を丸ごとシークレットに切り替える案(`isPrivateWindow` を可変にし、記録・表示に関わる所を実効の値へ切り替える)。
  約 180 か所を「窓の性質」と「記録・表示」に仕分けることになり、ノーマルの窓での振る舞い(決定 17)にも合わない。
- ファイル由来のメタデータ: 今の除外([ViewerViewModel] `isExcludedAppWide`)はメモリ上にも作らないが、シークレットウインドウと同じく
  メモリ上には作る(`ephemeralMetadata`)に揃える。

### 3.2 本を開かずに書くもの(場所で判定する。決定 9・10)
| 場所 | 書くもの | 扱い |
|---|---|---|
| `MetadataGenerator.run` の母体の絞り込み | メタデータの行 | 今の除外の述語を差し替える |
| `BookMetadataStore.upsertAll`(インスペクタ・メタデータの編集ウインドウ) | メタデータの行 | 断る(インスペクタは注意書き + 設定へのリンク) |
| `FileBrowserThumbnailProvider`(`savesToDisk`)・`BookLoader.load` の `cachesPageList` | 表紙のディスクキャッシュ・ページ一覧キャッシュ | URL ごとに書かない(読むのは許す) |
| `CollectionStore.insertItems`(追加の全経路が通る 1 か所)、`CollectionAutoFolderScanner` | コレクションの項目・表紙 | 断る。入り口は `canPerform` 系の同じ述語で淡色 |
| `SmartLibraryCatalog`(scan の結果)・`MetadataCorpusStore.recordSmartLibraryScan` | catalog.json・corpus.json | 外す(表示からも) |
| `FileBrowserVideoThumbnailWarmer` | 動画サムネイル | 先回りしない |
| `LayoutStore.existingOrNewSettings(forBookID:)`(表紙の指定) | レイアウトの行 | 断る(インスペクタ・書き出しの表紙欄) |
| `BookLayoutEditorViewModel` / `ExportWindowContent` の `PageLoader` | サムネイルのディスクキャッシュ | 対象の本ならディスクキャッシュを使わない |

「書かない」の判定は 2 系統(窓・場所)になるので、述語を 1 つにまとめ(例 `RecordPolicy`)、書き込み口はそれに尋ねる。何を書かないかの正典は
`AppState.isPrivateWindow` のコメントを拡張して 1 か所に保つ。

### 3.3 今のメタデータ用の除外(撤去)
`MetadataRulesStore`: `excludedFolders` / `isExcluded` / `isExcludedAppWide` / `appWideExcludedFolders` / `excludedFoldersDidChange`。
settings.json の `excludedFolders` は移行のために読むだけ残す。呼び出し元: `MetadataGenerator`(知らせと絞り込み)、`ViewerViewModel`、
`HomeInspectorMetadataSection`(注意書き・書き込みの判定)、`MetadataEditorView`(ツールバーのボタンと `MetadataExcludedFoldersSheet` は削除)、
`AppStores.folderSettingPaths`。テスト: `MetadataWorkspaceTests.excludedFolders`、`MetadataGeneratorTests.excludedAndDeletedBooks`。
今の一覧は保存データの書き出しに入っていない(`exportableRulesBundle` は規則の差分だけ)。

## 4. 実装の段階(案)

1. **置き場**: 新しいストア(パスだけ。末尾 `/` なし)。`qooViewer.pref.*` には置かない ―― 「初期設定に戻す」で黙って消え、記録が
   再開してしまうため。スレッドをまたいで読む写し(今の `appWideExcludedFolders` と同じ Mutex)、`FileSystemChange` での付け替え、
   `FolderSettingBookmarks` でのアプリ外の移動への追従(`folderSettingPaths`)。settings.json からの一度だけの移行と知らせ。
2. **本の判定と見た目**: シークレットフォルダの本を `leavesNoRecord` に加え(§3.1)、`leavesNoRecord` を見ていない所(ページ一覧キャッシュ)を
   塞ぐ。書き込みの判定は**読み込みの前**(要求の URL)、外観・タイトル・知らせは**新しい本が表示された瞬間**(`ViewerHandoff` が前の本を
   残している間に外観だけ先に変わらないように)に切り替える。
3. **ホーム側**: §3.2。
4. **UI**: 環境設定のペイン(一覧・＋/−・フォルダごとの残りの冊数・削除。削除は `DataUndoStack` で取り消せるように)、右クリック
   (`FileBrowserMenuCommand.groups(for:)` のアプリ固有のグループ。ファイルブラウザ機能 OFF で消える)、インスペクタの注意書きと
   「設定を開く…」(`SettingsNavigator`)、メタデータの編集ウインドウからの撤去。
5. **保存データの書き出し・読み込み**: `QooLibraryExportFile` に一覧を足す(`formatVersion` 7)。
6. **テストと文書**: 実効の判定の行き来(ノーマル → シークレット → ノーマル、シークレットウインドウでは変わらない)、各書き込み口、
   移行。文書は `AppState.isPrivateWindow` のコメント、docs/06「シークレットウインドウとその場限りの本」、docs/07(除外フォルダの節)、
   docs/09、docs/14、docs/15、CLAUDE.md。MANUAL/CHANGELOG は指示があったとき。

## 5. 実装(2026-10-03)

- 進め方は §3.1 のとおり `leavesNoRecord` に入れた(約 180 か所の仕分けはしていない)。本を開かずに書く所は §3.2 の表に加えて、
  コードレビューの指摘で **`BookLoader.load` の 1 か所でページ一覧のキャッシュを断る**形にした(保存データの書き出し・取り込み、表紙の抽出など
  呼び出し元ごとに足すと漏れた)。表紙の指定も `CoverOverrideController.allowsCoverChanges` で 1 か所で断る(書き出しウインドウのカバー列が漏れていた)。
- **タイトルの「(シークレット)」は `currentBook` で決める**(§1 の「新しい本が表示された瞬間」から変えた)。題の本の名前が `currentBook` で
  替わるので、目印だけ表示中の本で決めると「名前は新しい本・目印は前の本」が最長 300ms 混ざる。外観は §1 のとおり表示中の本。
- 環境設定のペインの「このフォルダの保存データと履歴を削除」は**取り消せない**(「保存データの削除」ウインドウと同じ削除の一式で、あちらも
  取り消せない。確認のアラートでそう伝える)。CLAUDE.md の「保存データの削除は取り消せるように」からは外れている。
- 移行の知らせは、最初に**見えている窓**が 1 秒後に出し、答えたときに済んだ印を付ける(コードレビューの指摘: 出す前に付けると、Finder から
  開いた起動で隠れた窓が印だけ消していた)。
- 実機の確認で見つけたもの: メニューバー「ファイル」の「コレクションに登録」(`Menu`)は `.disabled` が効かず押せる見た目のままだった
  (`.contextMenu` の中と同じ ―― 押せない `Button` で描く `FileBrowserDisabledSubmenu`)。判定も値の写し(`MenuCheckmarkState`)から引く。
- 実機(Debug、使い捨てボリュームの合成の本)で確かめたこと: 移行と知らせ・「環境設定を開く…」で該当の画面、右クリックの題の切り替え、
  シークレットフォルダの本で題の目印・外観・知らせ・編集メニューの淡色、外の本へ移ると元に戻る、保存データ(読書位置・メタデータ)・履歴・
  ページ一覧のキャッシュにシークレットフォルダの本が残らないこと(ノーマルの本は残る)、ペインの冊数と削除、インスペクタの注意書き。

## 6. 「常にシークレットウインドウで開く」(2026-10-03、続けての要望)

- 利用者の決定: 設定で ON/OFF(既定 OFF)。開き先も設定で選ぶ ―― タブ / その窓の本と入れ替え / 毎回新しい窓(前の 2 つは
  シークレットウインドウが無ければ新しく作る)。本を開くためだけに作られるノーマルの窓は「透明で起動して、透明なまま閉じる」ように、
  そもそも開いたように見えないこと。窓が 1 つも無い状態で Finder から開いたら、新しいシークレットウインドウは本来の窓(透明のまま
  閉じる主ウインドウ)が出るはずだった位置に出すこと。
- 実装と実測は docs/06「シークレットフォルダ」。実機(Debug、使い捨てボリューム)で、3 つの開き先、ノーマルの窓が中身のまま残ること、
  Finder から開いての起動でノーマルの窓が透明のまま閉じ、シークレットウインドウが同じ位置に出ることを CGWindowList で確かめた。
