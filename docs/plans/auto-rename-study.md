# 自動リネーム 検討メモ ―― よく使う項目の中の名前をバックグラウンドで整える

検討日: 2026-09-15 / ブランチ: `main`(まだコードは触っていない)

このメモは「作る前の検討」。ユーザーとの対話で決まったこと・設計案・要実測の事項を 1 枚にまとめる。
コードはまだ何も変えていない。

---

## 0. 要点

- **よく使う項目(またはその配下)のフォルダ**を対象に、アプリの起動中、置き換えの規則で名前を自動で変える。
- 形は「**1 つの規則 = 検索文字列と置換文字列の 1 組 + 対象フォルダの列**」(§2 の D 案)。メールの振り分けルールと同じ形。
- 規則は左の一覧の**上から順に**適用し、一覧のチェックボックスで ON/OFF する。
- 契機は起動時の走査と FSEvents(配下すべてに届く)。**ネットワークボリュームは対象にできない**。
- 対象フォルダが**消えたら、その対象だけを自動で OFF** にしてパスを淡色にする。ボリュームの未接続・権限の喪失とは区別する。
- 移動したと思われる対象は**一覧で提案し、対象ごとに更新を選ばせる**。
- 未決事項は §8 ですべて決まった(2026-09-15)。残りは §9 の実測。
- 大きな事故は 2 つ: 名前が伸び続ける規則(`a → aa`)と、書き込み中のファイルの名前を変えること。どちらも §5 で塞ぐ。

---

## 1. 元の要望(2026-09-15)

- ファイルブラウザのよく使う項目に登録されたフォルダ、もしくはそのサブフォルダだけを対象に、バックグラウンドで自動的に名前を変える。
- 名前の変更は、検索する文字列と置換する文字列の組。組を複数登録でき、任意の組をチェックボックスで ON/OFF できる。
- 対象フォルダだけでなく、サブフォルダも含めるかを設定できる。
- 設定の画面は 2 ペイン(左に設定の一覧、右に名前・対象フォルダ・サブフォルダを含めるか・置換の組)。
- ファイルブラウザのフォルダの右クリックからも設定でき、そのとき対象フォルダのパスは自動で入る。

最初の案(1 つの設定 = 対象フォルダ 1 つ + 置換の組の列)から、対話で §2 の形に変えた。

## 2. 設定の単位(決定: D 案)

| 案 | 1 つの設定の中身 | 評価 |
|---|---|---|
| A(最初の案) | 対象 1 つ + 規則の列 | 同じ規則を複数のフォルダに掛けると、フォルダの数だけ設定を作り規則を写すことになる |
| B | 対象 1 つ + 規則 1 組 | 1 フォルダに複数の規則を掛けると対象の設定が重複し、対象を移すときに書き換え漏れが起きる |
| C | 対象の列 + 規則の列 | ON/OFF が「設定」と「組」の 2 段になる。規則ごとに範囲を変えたければ設定を割るしかない |
| **D(採用)** | **対象の列 + 規則 1 組** | ON/OFF が一覧の 1 段で済み、規則ごとに掛ける範囲を変えられる。元の要望の「チェックボックスで ON/OFF」に一番近い |

D の弱点と、その埋め方:

- **適用順が一覧全体の並びで決まる** → 「上から順に適用」を画面に出し、ドラッグで並べ替えられるようにする。
- **新しいフォルダに既存の規則を全部掛けるには規則の数だけ対象を足す** → 右クリックのサブメニューで、規則ごとのチェックを入れるだけで対象に加わるようにする(§3.2)。
- 「名前が伸び続けないか」の判定と「試す」の単位は**フォルダ(項目)**になる。項目ごとに、掛かる規則全部を順にかけて判定する(§5.1)。

## 3. 画面

### 3.1 「自動リネームの設定」ウインドウ(独立ウインドウ。§8 の 8)

```
┌─────────────────────┬──────────────────────────────────────────┐
│ ☑ 規則 1 ⚠            │ 名前   [                          ]      │
│ ☑ 規則 2              │ 検索   [ foo    ]  置換 [ bar      ]      │
│ ☐ 規則 3              │        ☐ 大文字小文字を区別                  │
│                     │ ────────────────────────────────────── │
│                     │ 対象フォルダ                              │
│                     │ ☑ /Volumes/X/A     ☑ サブフォルダを含める  (−) │
│                     │ ☐ /Volumes/X/B     ⚠ 見つかりません       (−) │  ← 淡色
│ [+] [−]             │ (+ フォルダを追加…)                       │
│ 上から順に適用          │                                          │
└─────────────────────┴──────────────────────────────────────────┘
  (移動したと思われる対象フォルダが 2 件あります [確認…])  ← 該当があるときだけの帯
  (読み取り専用モードのため停止中)                          ← 読み取り専用モードの間の帯
```

- 左: 規則の一覧。チェックボックスで規則ごとの ON/OFF。ドラッグで並べ替え。対象が 1 つでも「見つかりません」なら規則名の横に ⚠。
- 右: 名前(空欄なら「“foo” → “bar”」のように中身から付ける案)、検索文字列と置換文字列、「大文字小文字を区別」(既定 OFF)、対象フォルダの一覧。
- 実行ログ(§8 の 7・9)の置き方(ツールバーのボタンで別のペイン/シートなど)は画面を作るときに決める。
- 対象フォルダの行ごとに ON/OFF と「サブフォルダを含める」。
- 「フォルダを追加…」は `NSOpenPanel`。閉じた後で、よく使う項目の配下か・ローカルのボリュームかを確かめ、違えば理由を出して断る
  (パネルの側で配下以外を淡色にすると、そこへ降りられなくなるため)。
- 開く場所: ファイルブラウザの右クリック、環境設定「ファイルブラウザ」のボタン、ホームメニュー(案)。
- 設定ウインドウは通常のウインドウなので、すりガラス面の縁取りの約束(CLAUDE.md)には当たらない。

### 3.2 右クリック(フォルダ 1 つを選んでいるとき)

```
自動リネーム ▶ ☑ 規則 1
              ☑ 規則 2
              ☐ 規則 3
              ─────────────
              新しい規則を作る…      ← このフォルダを対象に入れた規則を作って設定ウインドウを開く
              このフォルダで試す…
```

- 規則のチェックは「このフォルダがその規則の対象に入っているか」。入れる・外すがその場で保存される。
- 次のときは淡色(項目の数は変えない、いまの流儀): よく使う項目の配下でない、ネットワーク上、シークレットウインドウ。
- 淡色のサブメニューは、AppKit のメニューなら `isEnabled` で正しく出る(SwiftUI の `.contextMenu` の中の `Menu` は `.disabled` が効かない ―― docs/15)。

## 4. データ

`UserDefaults` の JSON(よく使う項目と同じ置き方)。SwiftData にしないので `StoreSchemaGuard` の世代は増えない。

```
AutoRenameRule {
    id, name, isEnabled,
    find, replaceWith,
    isCaseSensitive: Bool,     // 既定 false(§8 の 3)
    targets: [AutoRenameTarget]
}
AutoRenameTarget {
    id,
    path: String,              // 末尾の / なし。MountTable.normalized で揃える
    volumeUUID: String?,       // 登録時のボリューム(§6.1)
    bookmark: Data?,           // 移動の提案のため(§6.3)
    includesSubfolders: Bool,
    state: enabled | disabledByUser | disabledMissing,
    stateBeforeMissing: …,     // 移動の提案で更新したときに戻す値
    suppressesMoveSuggestion: Bool
}
```

- 上限: 規則 20・1 規則あたりの対象 20(§8 の 6)。
- 実行ログは別に保存する(件数の上限つき。置き場所は実装時に決める。「すべてのデータを削除」で消す ―― §8 の 10)。
- 読み取り専用モード・よく使う項目・権限・ボリュームの接続は**保存せず、実行時に毎回見る**(§6)。

## 5. 実行エンジン

アプリ全体で 1 つ(`AppStores`)。ウインドウごとの `FileBrowserOperations` とは別に置く(どのウインドウの操作でもないため)。

- 読み込みと名前の変更は `FileIO` の上(CLAUDE.md の約束。`Task.detached` にしない)。
- 名前の変更は `FileOperationService` の `RENAME_EXCL`・名前を正確に保つ経路(`FileNameValidation.validatedExactly`)。
- 置き換えの規則は `BulkRename` の「テキストを置き換える」と揃える(全部の出現を置き換え、拡張子が壊れたら元の拡張子を付け直す)。
  大文字小文字は規則ごとに選ぶ(§8 の 3)ので、置き換えの芯を切り出して区別の有無を引数にする。
- **読み取り専用モードの間は何もしない**(§8 の 1)。走っている 1 件は終わらせ、次から止める(`FileBrowserOperations` と同じ)。
- 対象: 対象フォルダの直下の項目(ファイルとフォルダの両方。§8 の 5)。「サブフォルダを含める」なら配下全部。
  対象フォルダ自身の名前は変えない。隠し項目・パッケージの中・シンボリックリンク先は扱わない。
  **フォルダの名前は中身を処理した後に変える**(先に変えると子のパスがずれる)。
- 1 つの項目に掛かる規則 = 「ON の規則」のうち「ON の対象がその項目を含む」もの、を一覧の順に。
- **アプリが起動している間だけ動く**。終了中の変更は次の起動時の走査で拾う。

### 5.1 名前が伸び続ける規則

`a → aa` は、自分の変更が FSEvents で戻ってきて `aaa…` になり続ける。`A → B` と `B → A` の 2 つの規則でも同じ。

- 項目ごとに、掛かる規則全部を**2 回かけて 1 回目と同じ結果になるときだけ**変える(f(f(x)) = f(x))。ならなければ変えずに実行ログに残し、設定ウインドウでその対象に警告。
- 入力の時点でも「置換文字列が検索文字列を含む」組に注意を出す。
- 自分が直前に変えたパスのイベントは読み飛ばす(判定上は何も起きないが、無駄な走査を避ける)。

### 5.2 書き込み中のファイル

Finder などのコピーの途中で名前を変えると、コピーした側と衝突しうる。

- 自動登録フォルダと同じ `CollectionAutoFolderScan.isSettled`(更新時刻が十分古い、または 0.5 秒空けた 2 回の観測で大きさと更新時刻が変わらない)を通ったものだけ変える。まだなら見送って後で見直す。
- Finder がコピー中の項目に付ける印も見るとより安全(要実測 §9)。

### 5.3 その他の見送り

- 衝突(新しい名前が既にある): **`name 2` で避ける**(§8 の 4。`BulkRename` の避け方 ―― 比べる相手はそのフォルダの名前全部、拡張子は登録済みの規則で分ける)。
  避けた名前は規則をかけた結果そのものではないので、**避けた後の名前にもう一度規則をかけて変わらないことを確かめてから**変える
  (検索文字列が `2` のような規則で、避けた名前がまた変わり続けるのを防ぐ ―― §5.1)。変わるなら変えずに実行ログに残す。
  相手が後で消えても、避けた名前は元に戻さない。
- 使えない名前になる(先頭のドット・空・`/`): 変えずに実行ログに残す。
- ビューアで開いている本、ファイルブラウザで名前を編集中の項目: 見送り、閉じた・確定した後に見直す。
- 本の保存データは、名前が変わってもファイルノードで追従する(開いたときの `reconcileBookIDIfMoved`、自動登録フォルダは inode で重複を弾く)。
  ファイルブラウザの手動の名前の変更と同じ扱いで、DB を直接書き換えることはしない。

## 6. 対象フォルダの状態

### 6.1 ネットワークボリューム(決定: 対象外)

- 「フォルダを追加…」で選んだフォルダがネットワーク上(`MountTable`)なら断る。右クリックの「自動リネーム」も淡色。
- 実行時にも確かめる(後から同じパスにネットワーク共有がマウントされうる)。そのときは「未接続」と同じ扱いで、削除扱いにしない。

### 6.2 見つからない対象(決定: その対象だけ自動で OFF)

**消えていないのに消えたと判定して OFF にする**のを避けるため、見つからない理由を分ける。

| 状況 | 判定 | 扱い |
|---|---|---|
| ボリュームは接続されていて、フォルダが無い(`lstat` が `ENOENT`) | 削除・移動された | **その対象を自動で OFF**(`disabledMissing`)。パスを淡色にして「見つかりません」 |
| ボリュームが接続されていない | 未接続 | 状態は変えず淡色で「ボリュームが接続されていません」。接続されたら自動で再開 |
| 同じ名前の別のディスクが同じ場所にマウントされている | 未接続 | 同上 |
| 権限が無い・取り消された(`EPERM` / `EACCES`、`FolderAccessStore` が覆っていない) | 権限 | 状態は変えず淡色で「アクセスを許可…」 |
| よく使う項目から外された(決定) | 条件外 | 状態は変えず淡色で「よく使う項目の外にあります」。よく使う項目に戻されたら自動で再開 |

- **「ボリュームは接続されている」は、パスが属するマウントの UUID が登録時の `volumeUUID` と一致したときだけ**。
  `st_dev` はマウント順で変わるので使わない。起動直後に外付けディスクがまだマウントされていない場合や、
  `/Volumes/X` が起動ボリュームに空のフォルダとして残っている場合も、UUID が違うので「未接続」になる。
- 判定の契機: 起動時・走査時・FSEvents でその対象(または祖先)が消えたと届いたとき。**1 秒ほど置いて確かめ直してから** OFF にする(一時的に名前を変えてすぐ戻す操作で OFF にしない)。
- **フォルダが戻ってきても自動では ON に戻さない**(ゴミ箱から戻した・同じ名前で作り直した)。別物かもしれないフォルダの名前を気づかないうちに変え始めないため。
  チェックを入れ直したときにまだ見つからなければ ON にしない。
- 同じフォルダを複数の規則が対象にしていれば、全部そろって OFF になる。
- 「利用者が OFF にした」と「見つからないので OFF にした」は状態を分けて持ち、後者だけ淡色と ⚠ を出す。

### 6.3 移動したと思われる対象の提案(決定: 一覧で提案し、対象ごとに更新を選ばせる)

見つけ方:

- 対象を登録するときにブックマークを保存しておき、`disabledMissing` になった時点と起動時に解決して新しい場所を探す。
- 見つかった場所を次で「更新できる / できない」に分ける: よく使う項目の配下か・ローカルのボリュームか・**ゴミ箱の中でないか**(ゴミ箱への移動でもブックマークの解決は成功する)・書く権限があるか。

知らせ方: 設定ウインドウの上部の帯「移動したと思われる対象フォルダが N 件あります [確認…]」と、左の一覧の ⚠。

確認のシート:

```
移動したと思われる対象フォルダ
┌───┬─────────────────┬─────────────────┬────────────┐
│更新│ 元の場所             │ 見つかった場所         │ 規則         │
├───┼─────────────────┼─────────────────┼────────────┤
│ ☑ │ /Volumes/X/A        │ /Volumes/X/old/A    │ 規則 1, 規則 2 │
│ ☑ │ /Volumes/X/B        │ /Volumes/X/B2       │ 規則 2       │
│ ☐ │ /Volumes/X/C        │ ゴミ箱の中            │ 規則 1       │  ← 淡色・選べない
│ ☐ │ /Volumes/X2/D       │ よく使う項目の外        │ 規則 3       │  ← 淡色・選べない
└───┴─────────────────┴─────────────────┴────────────┘
                                         [キャンセル] [更新]   ← 同じ幅
```

- **行はフォルダ単位**。同じフォルダを複数の規則が対象にしていれば 1 行にまとめ、更新すると全部の規則で書き換わる。
- 親フォルダごと移動した場合は、配下の対象がそれぞれ別の行になる。
- 更新できる行は最初からチェックが入り、できない行は淡色で理由を「見つかった場所」の列に出す。
- **チェックを外した行は、次に開いたときもまた提案する**。行の右クリックの「この提案を表示しない」を選んだときだけ出さない(`suppressesMoveSuggestion`)。
- 更新すると、パス・ボリュームの UUID・ブックマークを新しい場所で保存し直し、**見つからなくなる前の ON/OFF に戻す**。
  ON に戻る対象が 1 つでもあれば、既存の項目に掛ける前の確認(§8 の 2)を挟む(移動先には移動の前に無かった項目が入っているかもしれない)。

## 7. 契機(決定)

FSEvents はルートに渡したフォルダの**配下すべて**のイベントを届ける(サブフォルダごとに監視を張らない。fd も開かない)。
サンドボックス下で追加の entitlement なしに動き、他のアプリの変更も届く(qooLibrary で実測)。
1 本のストリームに「ON の規則の ON の対象」全部をルートとして渡す(`WatchRoot` は付けない ―― fd を使い切った件、`FolderChangeWatcher` の型コメント)。

| 契機 | 範囲 |
|---|---|
| 起動時 | ON の対象全部を走査 |
| 規則を ON にした・対象を足した・検索/置換・大文字小文字の区別を変えた | その規則の対象を走査(既存の項目に掛ける前の確認 §8 の 2) |
| FSEvents | 届いたパスの項目。**フォルダなら配下も**。`MustScanSubDirs` なら配下全部 |
| ボリュームのマウント | そのボリューム上の対象を走査。見つからない対象の判定・移動の提案もやり直す |
| 見送った項目の見直し | 書き込み中だった項目・開いていた本 |

届いたパスだけでは足りない場面:

- **同じボリューム内でフォルダごと移動してきた**: 移動は名前の変更なので、イベントは移ってきたフォルダ 1 件分だけで中身の分は来ない
  → 新しく現れたのがフォルダで、サブフォルダを含める対象なら配下を走査する。
- **イベントがあふれた**: FSEvents が `MustScanSubDirs` を送ってくる。いまの `FolderChangeWatcher` はフラグを捨てているので、
  **フラグも渡すように広げる**(qooLibrary の `FileSystemChange` に形がある)。
- **対象フォルダ自身が改名・移動された**: `WatchRoot` が無いので即座には分からない。祖先のイベントか次の走査で §6.2 の判定に落ちる。
- アクティブ化を契機にした走査は、ネットワークボリュームを対象外にしたので要らない(監視が張れなかった対象の回収に使うかは実装時に決める)。

## 8. 決定事項(2026-09-15、ユーザー判断)

| # | 論点 | 決定 | 補足 |
|---|---|---|---|
| 1 | 読み取り専用モード(既定 ON)との関係 | **止める** | 「ON の間はファイルを変えない」という約束を崩さない。止まっていることは設定ウインドウに出し、OFF にすると再開 |
| 2 | 既存の項目の扱い | **確認してから掛ける** | 規則を ON にした・対象を足した・検索/置換・大文字小文字の区別を変えたときは「今ある N 項目の名前を変えます」と変更前後の一覧で確認させ、承認したら掛ける。以後に現れた項目は自動 |
| 3 | 大文字小文字 | **規則ごとに選ぶ** | 規則に「大文字小文字を区別」のチェック。**既定は区別しない**(Finder の一括リネームと同じ)。区別しないときの規則(拡張子が壊れたら元の拡張子を付け直す)は `BulkRename` と揃え、区別するときも拡張子の規則は同じにする |
| 4 | 衝突したとき | **`name 2` で避ける** | 一括リネームと同じ避け方(§5.3)。避けた名前も「2 回かけて変わらないか」の判定に通す |
| 5 | 対象の種類 | **ファイルとフォルダの両方(固定)** | 設定項目は増やさない。必要になったら後で選べるようにする |
| 6 | 上限 | **規則 20・1 規則あたりの対象 20** | 後から広げるのは容易 |
| 7 | 実行の記録と取り消し | **記録は最初から、戻す操作は後の段階** | 変更前後の名前・見送りの理由を件数の上限つきで保存し、設定ウインドウに並べる。ウインドウの ⌘Z の履歴には積まない |
| 8 | ウインドウの名前 | **「自動リネームの設定」** / “Auto Rename Settings” | 環境設定のボタンは「自動リネームの設定…」 |
| 9 | 記録の画面での呼び名 | **「実行ログ」** / “Activity Log” | 「履歴」は本の履歴に使っているため(用語表) |
| 10 | 「すべてのデータを削除」「初期設定に戻す」 | **すべてのデータを削除だけ対象** | 規則と実行ログを消す。初期設定に戻すでは残す(よく使う項目と同じ扱い) |
| 11 | 保存データの書き出し(JSON) | **最初は含めない** | 規則はパスとボリュームに結びつき、別の機では効かない。必要なら後で |

## 9. 要実測

- Finder がコピー中の項目に付ける印(FinderInfo の種類など)を、書き込み中の判定に使えるか。
- サンドボックス下で、権限の無い場所へ移ったフォルダのブックマークからパスだけを得られるか(得られなければ提案の行は「アクセスを許可…」付きで出す)。
- 同じボリューム内でフォルダごと移動したとき、中身の分のイベントが来ないこと(FSEvents の一般的な挙動だが、この機では測っていない)。
- macOS 26 の FSKit 経由の exFAT で、イベントが漏れなく届くか。**FAT/exFAT のイメージの実測でシステムが固まったことがある**ので、並列のエージェントに任せず 1 つずつ行う。
- 自分の名前の変更のイベントが、判定上何も起こさないこと(2 回かけて同じ結果の確認)。

実機での確認は使い捨てボリューム(`hdiutil`)に合成名のファイルを置いて行い、実際の蔵書のフォルダは使わない。

## 10. 段階分け(案)

1. データ(§4)と置き換えの芯・2 回かけた判定(§5.1)の純粋関数とテスト
2. 実行エンジン: 対象の判定(§6.1・§6.2)・`isSettled`・`name 2` の避け方と避けた後の判定・見送り・実行ログ。使い捨てボリュームでのテスト(読み取り専用モード・よく使う項目の外・未接続と削除の区別・フォルダを後で変える順)
3. 設定ウインドウ(§3.1): 一覧の並べ替え・対象の追加と断り・淡色と理由・既存の項目に掛ける前の確認
4. 入口: 右クリックのサブメニュー(§3.2)・環境設定のボタン・メニュー
5. 契機(§7): `FolderChangeWatcher` にフラグを渡す拡張・移動してきたフォルダの配下の走査・マウントの通知
6. 移動の提案(§6.3): ブックマークの保存と解決・確認のシート
7. 実行ログからの取り消し(§8 の 7 で後の段階に決定)
8. docs/15 への反映。MANUAL / CHANGELOG は指示があれば
