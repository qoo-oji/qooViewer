# 応答の無い待ちの点検(2026-10-06)

利用者の依頼: 「操作に対し、インジケータの表示も何もないまま反応しない状態が人間が明確に体感できる程度の期間続くケースがないか、網羅的・系統的・
構造的に点検する」。対象は main `541492d`。点検の後、利用者の指示で下の「直すときの順番」の順に直した(末尾の「直した記録」)。

## 進め方

1. **洗い出し(10 の担当、コードを読むだけ)**: 機能で 8 つ(ビューア / 本を開く経路 / ファイルブラウザ / 本棚・コレクション・インスペクタ /
   スマートライブラリ・メタデータ / アプリ全体・メニュー・環境設定 / 書き出し・読み込み・補助ウインドウ / サイドパネル・本の中身ブラウザ)と、
   仕組みで横に切る 2 つ ―― **ブロッキングしうる API の呼び出し 1094 行+`URL(fileURLWithPath:)` 48 箇所を全件、どのアクタで走るか・
   どの操作から届くかで分類**、**期限・タイマー・直列の列・actor・ロック・`Task.detached`/`@concurrent`・表示の旗の全使用箇所**。
   担当ごとに「入口(利用者の操作)をまず全部挙げ、入口ごとに押してから画面が変わるまでを呼び先まで辿る」。
2. **検証(5 の担当)**: 1 の候補を反証するつもりで辿り直し、判定(確認 / 一部訂正 / 反証)と、頻度・長さ・見え方を付けた。
3. **実測**: 規模で決まるものを、テストホストの中で合成データで測った(最適化あり `-O`。保存先はメモリ上の SwiftData ―― ディスクの
   ストアでは遅くなる側)。計測のテストは一時的なもので、消してある。`URL` の属性値の控えの寿命も小さなプログラムで測った。

判定の基準: 操作から **0.5 秒以上**、受け付けたと分かる表示(回転表示・進捗・ハイライト・状態の変化・トースト・カーソル・ビープ)が
何も出ないもの。0.1〜0.5 秒は「もたつき」。条件は ①ふつう(ローカル SSD) ②規模が大きい ③遅い/応答しない媒体 ④別の重い仕事の最中。

型: **A** メインが同期で塞がる(ビーチボール) / **B** 非同期で待つが何も出ない / **C** 表示はあるが効かない・覆っていない /
**D** 別の仕事の後ろに並ぶ / **E** 待った末に黙って何もしない。

## 結論

- **ふつうの条件(ローカル SSD・ふつうの規模)の、よく使う操作には、体感できる無表示の待ちはほぼ無い**。ページ送りは先読みが効き、
  効かなくても見開きで 0.1 秒前後(デコードの実測 18〜48ms、`ImageDecoder.swift:86-87`)。
- 例外として、**ふつうの条件でも毎回起きるもの**が 2 つある: サイドパネルのフォルダ行のシングルクリックが**ダブルクリックの間隔(既定 約 0.5 秒)
  遅れる**(R8-1。以前 2 か所で直した不具合の再発)と、**次の本/前の本(同じフォルダ)で何も出ない探索**(R2-1。ローカルでは短い)。
- **実測でビーチボールが秒単位になったもの**が 2 つある: コレクションから外した本を ⌘Z で戻す(2000 冊中 200 冊で **3.5 秒**、1 万冊中 1000 冊で
  **110 秒**。R4-1)、保存データの読み込みでメタデータの行ごとにブックマークを作る(実在する本 5000 件で **8.6 秒**。R4-2)。
- 残りの大半は **遅い/応答しない媒体(眠った HDD・遅い SMB・応答しない共有)か、大きな規模**でだけ長くなる。根は 5 つに集約できる(下の「構造の根」)。
  とくに「**本を開く前の確かめ**」には共通の表示が無く、入口ごとに 0〜45 秒、何も出ないまま待つ(R2)。
- 利用者の今の保存データの規模(本番のストアの行数の集計): メタデータ 2,438 行・スマートライブラリの本 2,438 冊・コレクション 233・
  コレクションの本 2,402・ページごとのレイアウト 13,045・読書位置 170。**5 万冊を前提にした見積もり(スマートライブラリ・起動時の全件 fetch)は、
  今の規模では 20 分の 1 程度になり、体感の閾値を下回る**。コレクションと保存データの読み込みは今の規模でも秒単位。
