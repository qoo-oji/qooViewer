# 効率の監査(2026-09-25)

CPU・メモリ・ディスクの読み書きを、速さと機能を落とさずに減らすための総点検の記録。8 つの領域(本の読み込みとページ画像、
サムネイル・表紙、OFF の機能と起動時の仕事、複数ウインドウ・タブ、永続化、ファイルブラウザと見張り、スマートライブラリと
メタデータ、ビューアの描画)を読み、コードとコメント・docs の「採らなかった案」に照らして確かめたものだけを直した。
見た観点は次の 4 つ。

- OFF にしている・画面に出ていない機能のための仕事を走らせていないか
- 一度分かれば済む(小さな記録を残せば 2 回目から要らない)ことを毎回やっていないか
- 複数のウインドウ・タブで、同じものをウインドウごとに持つ・作り直していないか
- 既にある絵・一覧・値を使わずに、読み直し・復号し直していないか

## 直したもの

### 画面に出ていない・OFF の機能の仕事

| 何を | 以前 | 今 |
|---|---|---|
| サイドパネルのフォルダブラウザ(`SidePanelBrowserState`) | パネルを隠していても・別のモードでも・機能が OFF でも、アクティブ化・ボリュームの着脱・本を開くたびに、全ウインドウで一覧を読み直した(直下のフォルダごとに中を覗く) | 画面に出ている間だけ読み直す。出ていない間は印だけ付け、出たときに読む(`setVisible`)。前のフォルダの行は捨てる |
| 本の中身ブラウザ(`BookContentsBrowserState`) | 本を開くたびに作り(書庫をもう 1 度開いて一覧を取り、開いたまま持つ)、ページ送りのたびに追従した(章の境界で書庫を開き直し、入れ子の書庫をメインで展開) | ブラウザモードの下段が出ている間だけ作り・追従する(`ContentView.isBookContentsPaneOnScreen`)。出たときに今の本・今のページへ追いつく |
| お気に入り(`FavoritesFeature.isEnabled == false`) | メニューを閉じるたびの 2 回のフェッチ、アクティブ化・着脱・ファイル操作のたびの全件のブックマーク解決と stat | 始めない(データは読み込んだまま。フラグを戻せば元どおり) |
| 書き出しウインドウの VM | 一度開くと、閉じた後も知らせのたびに対象全冊のブックマーク解決と実在確認 | 閉じている間は印だけ付け、次に出たときに読み直す(`BookExportViewModel.setPresented`) |
| リソースモニタの計測役 | 毎秒の発火が App の body とメニューを作り直した | `allObjectWillChangePublishers` から外した(どのメニューも読まない) |
| サムネイルのメモリ | 機能を OFF にしても最大 96MB + 96MB を抱えたまま | ファイルブラウザとスマートライブラリの両方が OFF / ライブラリが OFF になったら手放す |
| スマートライブラリの本集め | ウインドウを閉じたときに onDisappear が来ないと「出ている」のまま残り、集め直し続けた | 画面ごとの印(`activate(client:)`)にし、`willClose` からも外す |

### 一度分かれば済むこと

| 何を | 以前 | 今 |
|---|---|---|
| ComicInfo.xml・EPUB の目次・PDF のアウトライン・EPUB/PDF の書誌情報 | ファイルに何も無いと取り込んだ印が付かず、開くたびに探し直した(PDF は 2〜3 回開き直して解析) | 「無かった」ことを構造キャッシュの項目に覚える(`BookPageListCache.Entry.sourceProbe`。指紋が同じ間だけ)。`didImportSourceMetadata` を立てないのは、印の無い行だけが掃除の対象(`isParsedOnly`)だから |
| 構造キャッシュ(`BookPageListCache.store`) | 開くたびに同じ中身を書き直した | 同じなら書かない(鍵を並べて書くのでバイト列が揃う)。刈り込みのための更新日時は古いときだけ触る |
| 起動後のアプリの外での移動の追従(`ExternalMoveSweeper`) | 動いていない本(ほぼ全部)でも、フォルダの本の中を読んだ | ブックマークが記録どおりの場所を指す本は中を読まない(`BookExistenceProbe.movedDestination`) |
| メタデータ生成(`MetadataGenerator.noteBookOpened`) | 2 度目以降に開いた本でも 1 回ぶん(約 0.1 秒)をメインで走らせた | 並べていて行もある本は回を頼まない |
| スマートライブラリの `catalog.json` | 起動後の最初の集め直しで同じ中身を書き直した | 読んだものを「最後に保存した一覧」として覚える |

### 同じものの作り直し・読み直し

| 何を | 以前 | 今 |
|---|---|---|
| ファイルブラウザ・スマートライブラリの絵 | 表紙が 1 冊できるたび(`revision`)に、見えている全セルが(全ウインドウで)頼み直し・CGImage の作り直し・描き直し | 出どころの鍵(`FileBrowserThumbnailProvider.sourceKey`)が変わったセルだけ頼み直す |
| スマートライブラリの表紙のセル | 幅が 1pt 変わるたびに頼み直し、帳簿に積んでグリッドの作り直しを呼び込んだ。body のたびに切り直した | 段(tier)が上がったときだけ引き直す。切った絵は控える(`CropCache`) |
| コレクションの中の表紙 | 戻るたび・作り直すたびに全セルが JPEG を読み直して復号した | アプリで 1 つの復号済みのキャッシュ(`CollectionCoverStore.memoryCache`) |
| コレクションの本の並べ替え | 1 回の描き直しで 5〜6 回、全冊を並べ替えた | 同じランループの中は控えから返す(鍵に中身・日付・タイトル・並び・検索語) |
| 表紙の抽出役 | 1 冊終わるたびに全登録を走査して積み直した(冊数の 2 乗)。ブックマークの解決と存在確認をメインで | 結果を書いただけの知らせでは積み直さない。解決は `FileIO` で。`item(withID:)` は索引で |
| 本を開くとき | Bookmark の全件を 2〜3 回フェッチ。ファイルの識別子を最大 7 回求めた | 1 回ずつ |
| メタデータの全行(`BookMetadataStore.allRecords`) | 呼ぶたびに全行から作り直した | `revision` が同じ間は控えを返す |
| スマートライブラリの絞り込み | 1 文字打つたびに全シェルフを全冊に当て直し、全冊の欄を畳み直した | シェルフの結果と検索の文字列を控える(本・シェルフ・分が変われば作り直す) |
| ファイルブラウザの一覧 | 読み直しのたびにメインで並べ替え、中身が同じでも一覧を作り直した(reloadData) | 並べ替えは `FileIO` で。同じなら差し替えない。絞り込みの名前は 1 度だけ畳む |
| 付け替えの知らせ | 本を問わない知らせで、開いている全冊のビューアが全件フェッチと組み直し | 付け替えた本の ID を付ける(`BookRelocationPlan.relocatedBookIDsUserInfoKey`) |
| ファイル操作のたびの実体の確かめ直し | どんな操作でも登録した全冊のブックマーク解決と stat | その一覧の本に関わる変更のときだけ(`FileSystemChange.touchesAny`) |

### 細かいもの

- ディスクキャッシュの「最終アクセス」は、当たるたびではなく 1 時間より古いときだけ書く(`DiskCacheAccessStamp`)。
- サムネイルのディスクキャッシュが OFF の間は、読みの問い合わせも書き込みの Task も作らない。
- リソースモニタのディスク容量は、コンテナを 1 回だけ辿って内訳へ振り分ける。
- 拡大鏡: マウスの移動では前と今のレンズの範囲だけ描き直す。`dismantleNSView` で閉包・画像・追跡範囲を外す。
- カーソルの自動非表示は、マウスが動くたびに Task を作り直さず 1 つを待ち直す。
- パスだけ使う `URL(fileURLWithPath:)` には向きを渡す(向きを知らないと stat する ―― ネットワークの本では往復)。
- キーの割り当ての保存は、変わった 1 つだけ書く。

### 直している途中に見つけた不具合

- 中身が差し替わったと判断した本のブックマークを消したとき、知らせを出していなかった(ブックマークの編集ウインドウの一覧が
  消した行を持ち続けた)。
- 表紙の抽出の最中に表紙の指定を変えると、終わった抽出が古い絵で `.ready` にしていた(`redoAfterExtraction` へ積むようにした)。

## 見送ったもの(理由つき)

| 案 | 見送った理由 |
|---|---|
| 背景のウインドウ・タブのページ画像のキャッシュを、見えない間だけ小さくする(全体の予算) | 戻ったときの最初のページ送りが遅くなる。上限は「1 冊あたり」と利用者に見せている値なので、振る舞いを変えるには利用者の判断が要る |
| 覆われた・背面のタブの FSEvents・読み直しを止める(`occlusionState`) | タブの切り替えで onAppear/onDisappear が来るかの実機確認が要る |
| サイドパネルへ渡す閉包を束ねてページ送りのたびの再評価を止める・ページの位置を AppState から外す | 大きなファイルにまたがる組み替えで、実機で描き直しの回数を測りながらでないと危ない |
| 見開きの拡大鏡用の結合画像をやめ、ページごとに描く | 継ぎ目の見た目を実機で確かめる必要がある |
| よく使う項目の中の動画の先回りを、FSEvents の履歴の再生にする | 新しい経路が大きい。取りこぼしても先回りが遅れるだけで、今の全走査も意図した動作 |
| 起動時の本ではないフォルダの掃除に「確かめ済み」の控えを持つ | 子フォルダの変化が親の更新日時に出ないので、控えの持ち方に利用者の判断が要る |
| ファイルの書き込み中の FSEvents による読み直しを 1 秒に 1 回へ間引く | 大きさ・日付の列の更新が遅れる(見える変化) |
| アクティブ化のたびの実体の確かめ直しを間引く | Finder での変化の反映が遅れる(見える変化) |
| ライブラリが OFF の間のレイアウトの変化の記録を絞る | 記録の持ち方に利用者の判断が要る |
| サムネイルの段を互いから作る(240px をグリッドの段から縮めるなど) | 二段の縮小でわずかに甘くなる。画質の判断が要る |
| コントラスト補正のグレーのページを 1 バイトのまま持つ | 色空間の扱いが変わり、見た目の比較が要る |

## 確かめ方

Linux のコンテナで Swift 6.2 の構文検査と、Foundation だけで組める部分(`FileSystemChange.touchesAny`・`StorageUsageScanner`)の
動作確認をし、CI(macOS 26 / 27)でビルドとテストを通した。画面の振る舞い(サイドパネルの追いつき・拡大鏡の描き直し・
カーソルの自動非表示)は実機での確認が要る。
